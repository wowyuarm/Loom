## 0. 为什么从 after-chat 入手

after-chat 是"更大的主动"的最小缩影。pulse（定时脉冲）、机会识别、节律这些更大的主动，都会反复用到同一套骨架：

1. **什么时候醒**（触发源）
2. **醒来看什么**（候选材料）
3. **谁来决定**（jev 提议 vs 主体处置）
4. **怎么防过度**（不让主体变话痨 / 不无谓唤醒）

after-chat 是这套骨架里最便宜、最安全的一片：agent 本来就刚醒着（刚回完话），不需要新的定时/唤醒基建，判断错了顶多多说一句或不说。所以先拿它把"jev 之于主动性"的骨架实验清楚，再往需要真正定时源的更大主动延伸。

**【约束】** 这不是赶一个小功能，是拿最安全的一片做骨架实验。真实中文对话上的校准是往下走的硬前提。

## 1. jev 是什么（选型相关要点）

【事实，来自 typesafe.ai 文档 + 真实调用】

- jev 是"System One"快模型：不生成文字，只对一个 `state` 评估一批结构化"问题"，并行、互不干扰地返回结构化答案。约 70–500ms，极便宜。
- 三种原语（可在一次调用里混用）：
  - **Noul**：是非题 → 单个概率 0–1。**无**置信度字段。
  - **Choice**：从最多 255 个选项选一 → `choice` + 每项 `probabilities` + `confidence`(0–1)。
  - **Score**：按 rubric 打分 → `score` + 每档 `probabilities` + `confidence`(0–1)。
- 官方主推用法：把大判断拆成原子小问题，在代码里组合；用 `confidence` 做三档门控（高→自动、中→谨慎/确认、低→不动）。阈值随风险调，不是一个全局数。
- 接入：OpenRouter `POST /api/alpha/decisions`，native TypeSafe schema，model `typesafe/jev-1.13`（非聊天端点）。Score 的 `criteria` 在该端点须为**数组**（Noul/Choice 为对象）。每次小调用约 ¥0.0001。**非免费**，走 OpenRouter credits。
- **【约束】中文非主训练语言**：文档明言 CJK 能处理但不如英语，任何阈值必须在真实中文对话上验证过才可信。

## 2. 三原语怎么选——同场景对照实验

【实验，2026-09-28】同一个偏边界场景（用户提"妈生日没想好礼物"又说"睡了"），一次调用同时问三种：

| 原语 | 结果 | 读出 |
| --- | --- | --- |
| Noul（是非闸门） | 0.63 | 干脆的"要不要醒"，但**无置信度**，也不给方向 |
| Score（价值打分） | 1.44，**置信仅 0.16** | 中间地带置信天然塌陷；能反映"有多暧昧"但只给笼统量，不告诉你做哪件 |
| Choice（选方向，带 none） | followup_topic 0.76 / 置信 0.64 | 在候选里挑向；置信低=它也没把握，该浮多件 |

【实验补充，2026-09-28】"只用一种"两条路都跑了：

- **只用 Choice**（候选各一项 + 一个 none）：rich → `act_deferred` 0.75 / 置信 0.69（none 仅 0.02）；收尾（改名+谢谢）→ `none` 0.77 / 置信 0.71。**它自己就把"不该动"表达成 choice=none**——`none` 胜出 = 闸门关。一次调用同时给出"要不要动 / 动哪件 / 多大把握"。
- **只用 Score**（0=安静，2=明显活线）：rich → 1.6 / 置信 0.40；收尾 → 0.28 / 置信 0.59。能分出该不该动，但**只给笼统量、不给方向**，还得再问一轮定方向；置信在中间地带塌，反不如 Choice 稳。

### 【决策，Human 确认 2026-09-28】单 Choice + none + 三档置信门控

> **只用一个 Choice**：候选各占一项 + 一个 `none` 逃生口。一次调用承载整个判断。
> - `none` 胜出 = 不唤醒主体（零主模型成本）。`none` 的 confidence + 选项本身就替代了单独的 Noul 闸门。
> - 非 none 胜出 = 按 Choice 的置信度做**三档门控**（下）。

- **Noul 不用**：没有置信度，也不给方向。
- **Score 不用**：连续的"暧昧度"被 Choice 的置信覆盖，还得补一轮问方向，多问只增本。
- **绝不 argmax**：一个真正相近的两候选场景，Choice 置信掉到 0.64、概率摊开——**置信度本身就是防局部最优的信号**。

### 三档置信门控（核心决策规则，主体看不到 raw 分）

- **高置信** → 浮一件（Choice 选中的那件）给主体。
- **中置信** → 把前几名一起浮给主体，让主体（真正的 System 2）自己权衡，jev 不锁死。浮 **top-3**（Human 定 2026-09-28）。
- **低置信 / none 胜出** → 安静，不唤醒主体。

**【开放】** 高/中/低的具体分界线，必须拿真实中文对话样例回归定，不拍脑袋。

### 【重大修订，Loom agent 提案 2026-09-28】Choice 问「动作类型」而非「哪条线」——候选构造问题被绕开

Loom agent（主体自己）对这套骨架提了一个更利落的重构，实验证明大体成立、且顺手化解了上一轮卡住的「候选构造」frontier：

1. **jev 前面先加一道确定性闸门（jev 看不到）**：距上次互动多久、冷却、今日主动次数、他是否在忙——过了才轮到 jev。保守放代码，不写进 jev 指令（否则和 jev 校准打架）。这条把 §3.3 里含糊的"conservatism in code"变成一道显式前置闸，且严守 jev 只提议不决定。**采纳。**
2. **Choice 不再是"每条活线各占一项"，而是一个固定的动作类型词表**：`quiet`（=原 none，安静）/ `continue`（接刚聊的线）/ `raise`（引新线）/ `flag`（提醒具体的事）/ `do`（主动做件事，不必开口）。"具体哪条/哪件"要么补第二问，要么直接把 Q1 结果丢给 main agent 自己展开。
   - **这一步顺手化解了 §3.2 的候选构造难题**：jev 不再在动态构造的候选串里挑，attention/threads 原文直接进 `state`（不必归一化成干净选项串），jev 只挑一个动作姿态，"具体做什么"交给 main agent（真正的 System 2）。上一轮"规则 vs 轻模型构造候选"的开放项因此大幅缩小——只剩最近对话切片仍需拼。
   - 代价：丢掉了原设计里 jev 给出的"线 A vs 线 B"逐条置信/排序。判断：可接受，逐条权衡本就该是 System 2 的活。

### 【实验，2026-09-28 用真实 attention/threads 跑 5 选项动作 Choice】关键发现：阈值规则要改

真 jev 调用，state = 真实"我在意的几条线"（attention 两条 + threads 一条归一）+ 最近对话切片 + 时机事实。四个中文场景：

| 场景 | 胜出 | P(胜出) | quiet | conf | 应否唤醒 |
| --- | --- | --- | --- | --- | --- |
| A 明确 deferral（"待会帮我列周报"+他去开会） | do | 0.53 | 0.27 | 0.41 | **应** |
| B 收尾（改名+谢谢+就这样） | quiet | 0.91 | 0.91 | 0.88 | 不应 ✓ |
| C 暧昧（"文章先放放，想好叫我"） | quiet | 0.71 | 0.71 | 0.63 | 不应 ✓ |
| D 未交付的承诺（"周报你说好了列，怎么没看到"） | do | 0.69 | 0.11 | 0.62 | **应** |

**核心发现**：Loom agent 提的采纳规则「P(最优非 quiet) > τ，τ 初始 0.7–0.8」在 5 选项下太严——概率被 5 项摊薄，**连该唤醒的 A、D 都只到 0.53 / 0.69，全在 0.7 之下 → 会被压成不动**。这正验证了"每加一个选项都摊薄概率"。5 选项时没有一个场景能过 0.7，规则会把主动性阉掉。

**⇒ 改阈值锚点：不 threshold 胜出项的概率，改 threshold `quiet` 的概率。** quiet 低（<~0.4）→ 唤醒，取非 quiet 里最高者作动作姿态；quiet 高 → 安静。这套规则在四场景上干净分开（A quiet 0.27 / D 0.11 → 唤醒；B 0.91 / C 0.71 → 安静），既守住 Loom agent"quiet 只是一个选项、不问二值醒不醒"的本意，又躲开摊薄。**【决策，Human 确认 2026-09-28】** 判据锚在 `quiet` 概率、初值 ~0.4。是否保留全 5 选项还是收到 3 项仍待真实回归（【开放】）。

**【实验注意】** 该端点 Choice 的选项字段名是 `criteria`（对象 {key:描述}），不是 `options`；否则 400。此前笔记只记了 Score 的 criteria 须为数组，Choice 的 criteria 是对象——此处补全。

### 【实验，2026-09-28 逐姿态可分性测试】5 个动作 jev 分不清——建议收成 3 档

Human 追问"这几个动作 jev 真选得出吗、价值确定吗"。做了针对性实验：对五个动作各造一个"最该选它"的场景，看 jev 是否真会挑中：

| 想让它选 | jev 实选 | 目标项概率 |
| --- | --- | --- |
| continue（接半截话题） | **quiet** 0.55 | continue 仅 0.25 |
| raise（引新线） | **quiet** 0.86 | raise 仅 0.01 |
| flag（提醒承诺） | do 0.61 | flag 仅 0.27 |
| do（动手做托付的事） | **do** 0.86 | ✓ 干脆 |
| quiet（收尾） | **quiet** 0.90 | ✓ 干脆 |

**结论：jev 稳的只有 `do` vs `quiet` 两极。`continue/raise/flag` 即便在为它们量身造的场景里也几乎不胜出**——continue 被 quiet 压、raise 几乎归零、flag 被 do 吃掉。这印证了 §1 的老教训（jev 擅长具体存在性判断，不擅长细腻社交姿态区分）和"每加一个选项摊薄概率"。**五个动作的"价值确定性"不成立**——语义太近、jev 挑不开，摊薄还害了该唤醒的场景（见上一节 A/D 掉到 0.5–0.7）。

**⇒ 建议把动作域收成 3 档**：`quiet` / `speak`（开口——接话或引线，具体接什么交主体）/ `act`（不必开口、去做件事——含提醒/整理/执行）。粒度粗、每档语义拉开、概率不被稀释，jev 能挑得开；"具体说什么/做什么"本就交回主体（§3.4 已定）。这跟"安静概率做闸门"的判据完全兼容：quiet 低就醒、看 speak/act 谁高定姿态。**【决策，Human 确认 2026-09-28】三档定案。** 语义：**speak** = 另起个他会在意的话题 / 之前聊到觉得值得再说一句 / 关切；**act** = 一般来自过往交流 + attention/threads，或一个明确"该马上做"的信号；quiet 是默认多数。

### jev 结果怎么进 prompt、表现会怎样（Human Q1 后半）

- **进 prompt 的只有过闸后整理的一小段自然语言情境，绝无 raw 分**（§3.4 已定）。姿态（speak/act）只用来定情境的措辞语气：`speak` → "……可能可以跟他说一句"；`act` → "……可能可以先把它做了"。姿态本身不写进 prompt 当指令，只塑形那段情境。
- **【开放·无真实证据】** 主体拿到这段情境后的真实表现（会不会显得做作、会不会过度顺着 jev 的姿态走）——这必须等真跑起来看，现在只有手造场景，零真实模型回路证据。列为第一片上线后的首要观察项。

## 3. after-chat 探针的骨架

### 3.1 触发（什么时候醒）

【事实，源码已核】

- DSH 有 `agent/turn-stopping` 边界：模型这一回合没有要回的东西、要提交时触发。现在 `src/channels/index.ts` 已在骑它做"回复写了没发出去"的追问。
- **after-chat 就地接续挂同一个点**，不造新唤醒基建。
- "聊天真的停了"有现成信号：`src/time-context/projection.ts` 的投影一直记 `lastEventTime`（最后一个模型可见事件时间），距上次多久已每轮注入，可直接用来判"聊完歇下来了"。

**【约束】** 第一片只做"就地接续"这一半（骑 turn-stopping / idle，主体已醒）。真正的"延后唤醒"（需要**持久**唤醒源的那一半）留给更大的主动，本片不碰。

### 3.1a 触发时机 + 并发模型（Human 确认 2026-09-28，源码已核）

**修正上一版"不造定时器"的说法**——关键区别不是有无定时器，而是定时器的寿命与归属：

- **第一片用一个一次性的静默计时器**：对话一停（agent 回完进 idle），挂一个 `random(3–14min)` 的一次性闹钟，只活在这次静默里、纯插件本地、不跨重启、无人时不长期空转。延迟本身有用（立刻接会撞上他还在打字；等几分钟静默才算"真停"，随机化去掉整分钟敲门的机械感）。**采纳。**
- **推迟的是持久唤醒源**：几小时后才响、跨进程重启仍在、脉冲节律——留给更大主动。边界就在这。

**总原则：真人消息永远压过主动检查。** 四个边界情况（Human 提）：

1. **闹钟未响他先发消息** → 来的真人消息是正常反应式回合，**取消待响闹钟**，正常回，重新静下来再挂新闹钟。
2. **检查进行中他发消息** → jev 检查跑成 **`agent.runMaintenance`**（从 idle 起的非回合任务，其间进 inbox 的输入停着不丢，见 dsh-agent runtime-types.d.ts:165)。检查完若要醒但 inbox 已有新消息 → 放弃这次主动、让位。若主动回合已在组话你才发 → 你的消息按 **steer 在下个 step 边界（当前 tool call 结束后）插入**，模型就地转去回你。这正是 Human 说的"默认 steer、等 tool call 结束插入"。
3. **检查后（回合已结束）他发消息** → 普通反应式回合，无特殊处理。
4. **响了再过 3–14min** → 靠代码闸门兜：**冷却**（无次数上限，Human 定 2026-09-28）。

**代码闸门（重申 + 具体设计，Human 确认 2026-09-28）**在 jev 前、jev 看不到。守两件事：花不花这次 jev 调用、过 jev 后要不要真唤醒。**状态极少、纯插件本地：只一个 `lastWakeAt`（上次真唤醒 speak/act 的时间），无计数器。**

- **【决策修订，Human 2026-09-28】第一片先不设冷却、不设次数上限——从效果出发。** 只保留结构性的"一次对话停顿至多一次检查"（这个必须留，否则后台空转）。冷却（曾定 30min）和次数作为"观察到黏人循环再加"的已知旋钮留着、不预先拧。
- **唤醒判据不变**：quiet 概率 **< 0.4 → 唤醒**（≥0.4 不唤醒），取 speak/act 里高者定姿态。（Human 一度以为改了——只是换了说法，规则未动。）
- **"循环"担忧的真正解法不是冷却，是结构 + jev 自身**：(1) 结构——闹钟只在对话停下时挂、响过不自动重挂，只有他真的回了产生新停顿才有下一次；他不理就没有下一次。(2) jev 自身——收尾场景 jev 返回 quiet 高（实验"改好了谢谢就这样"→ quiet 0.90），对话往"聊完"走时下一次 after-chat 会自己安静。真正的循环只发生在"每次都实质接话、话题真的一直活着"——那本就是该继续的对话，不是骚扰。冷却只是防"话题淡了但 jev 误判还想说"的保险丝，故可后加。
- **"他忙不忙"第一片不单独造信号**，用"静默够久"近似。
- **上线后必须观察（只有真实效果能答）**：会不会出现 jev 没收住的黏人循环；3–14min 延迟体感对不对。

【历史备选，未采纳】曾设计 30min 冷却 + 无次数上限；冷却只挡唤醒不挡 jev 检查。Human 选择先不设、看效果。

**followup → steer 的改动**：现在 channels 入站走 `agentRuntime.deliver()` = `agent.followup()`（开独立新回合，runtime.ts:130-134, channels/index.ts:220）。主动这条路（乃至入站消息）改成 **steer 在下个 step 边界插入**更对——不打断正跑的 tool call，也不另起竞争回合。**落地待定细节**：steer 语义比 followup"软"（step 被拒 / agent 被弃时 steer 可能被丢弃，runtime-types.d.ts:193-200），到底用 `steer` 还是带 target 的 `send(msg, target, wakeup)`（:186）须对着 DSH 语义敲定；方向（别另起竞争回合、下个安全边界插入）确定。

**连续性钩子**：主动回合发出的内容标一个自己的 source，让 `isEphemeralNotice`（continuity host 已给主动性留了这个钩子，host.ts:110-118，v1 默认返 false）在换代时"重新推导而非重读"它。

### 3.2 候选材料（醒来看什么）

【事实 + 判断】优先级（Human 确认）：**最近对话首要**，然后 attention，然后 threads index。

**候选（= Choice 的选项）是运行时动态拼的，不是预先写死的固定枚举。** 每次 after-chat，代码现从这三处扫出当前的候选，各占 Choice 一项；唯一固定的选项是 `none`。所以选项集每次都不同——jev 面对的永远是"此刻实际存在的那几条线"。没有"匹配到 X 就走某分支"的硬编码。

- **最近对话**（首要）：从 session 事件还原一来一往。**【约束】对外真说出去的是 `message` 工具的 `text` 参数**（普通 assistant 文本谁都收不到），用户侧是 user 消息——两者都要抓。
  - **【实验，2026-09-28 看了三条真实 session】提取规则的形状**：
    - **人类侧短、Loom 侧长**：真实人类消息几乎都是一句话（多 5–25 字，偶尔一条 URL；**原文样例已脱敏，此处只留长度与形态**）；Loom 的 `message.text` 回复常几百字。所以按"轮数"截而不按字符平均截——**人类侧整条留，Loom 侧每条截首段/前 ~150 字**（活线信号几乎全在人类留下的话里，Loom 长回复只需留个上下文钩子）。
    - **人类消息带来源前缀**要剥：真实内容形如 `[<channel> · direct · from <人名>]\n<正文>`——第一行是通道元信息，喂 jev 前去掉。
    - **必过滤 runtime-context 快照**：`user/message` 里 `source.kind='runtime-context'`（form='snapshot'）是注入的上下文、不是人说的话（470–716 字），混进去会污染"最近对话"。只取 `source.kind='user'`。
    - **【判断】切片粒度 = 最近 1–3 轮 human↔loom 往返**（一轮 = turn/start…turn/end）。三条真实 session 每条对话就 2–4 个往返，取到 3 轮基本覆盖整段近对话；再加"每条 Loom 侧 ~150 字上限"兜住极端长回复。这条够 after-chat 用，不必按 token 精算。
  - **【开放】** 1 轮还是 3 轮的确切值、Loom 侧截断长度，等阈值一起在真实中文回归里微调；当前形状已够搭第一片。
- **attention**：`attention/attention.md` 常驻内容，本来每轮就在。
- **threads index**：`threads/index.md` 里休眠的活线（一行一条）。

**【新问题，2026-09-28 用真实数据发现——候选构造这一环之前漏了】**

用 Loom 里**真实的** attention（两条）+ threads（一条）+ 一个"最近对话活线"选项跑真 jev：选了"最近对话活线" 0.56 / **置信仅 0.45**、none 还占 0.16。暴露两点：

1. **attention/threads 的原文是写给主体自己看的备忘，不是写给 jev 判的选项。** 例：真实 attention 有一条尾巴是"这条线第一次由他起头，若他往下推从这里接"——jev 拿整段当选项描述会犯迷糊。**选项描述需先归一化成"一句干净的活线陈述"。**
2. **"最近对话的活线"不是静态选项**：attention/threads 有现成一行，最近对话没有——得由代码/一次轻判断从最近几轮把"用户留下的悬念"拎成一句。原图轻描淡写"候选各占一项"，但**最重要的那一项（最近对话）恰恰最难构造**。

**⇒ 候选进 Choice 前必须有一个「候选构造」步骤**：把三源各归一化成"一句干净的活线陈述"。attention/threads = 清洗 bullet 首句；最近对话 = 从 session 最近几轮拎悬念。**【开放】** 这一步用规则（便宜、脆）还是补一次轻 jev/轻模型（准、增本），待用真实数据多试后定。

**【判断】** 候选合计控制在个位数（≤ 6–8 项）+ 一个 none：最近对话的活线全列（一般 1–3 条），attention/threads 各取最相关的少数，避免稀释信号。

### 3.3 jev 判断（谁来决定的第一半：提议）

**一次 jev 调用、一个 Choice** 承载整个判断（【决策】见 §2）：

- **一个 Choice**：候选（来自 3.2）各占一项 + 一个 `none`（"没有真正值得的，安静不动"）逃生口。指令措辞形如"此刻 Loom 最该做的主动之事是哪一类？没有就选 none"。
  - `none` 胜出 = 闸门关，不唤醒主体，零主模型成本。
  - 非 none 胜出 = 按置信度三档门控（§2）。
- **【实验】问题/选项措辞是最要紧的参数**：
  - 候选描述锚在"有没有具体活线/明确留下的事"，**别用**"现在开口合不合适"这种社交感受——后者在该接/不该接场景都给 ~0.65，不区分。
  - **【开放】反话痨**：早前对 Noul 闸门加"不要因为想显得关心就倾向 yes"能把偏冷场景从 0.85 压到 0.57。换成单 Choice 后，等价手段是 `none` 选项的描述写得够"给台阶下安静"，并观察收尾场景 none 是否够稳、会否被话痨偏向压低。需回归校。

**【约束，来自 DESIGN §9】** jev 只提议信号、绝不改状态；**主体永远看不到 jev 的 raw 打分**。代码在置信度上门控，只把整理好的情境交给主体。

【实验佐证】

- 只用 Choice：rich 场景选 `act_deferred` 0.75 / 置信 0.69（none 仅 0.02，开门）；收尾场景选 `none` 0.77 / 置信 0.71（关门，零主模型成本）。
- （早前分源 Noul 打分亦佐证排序合理：用户托付 0.90 > 刚提头疼 0.46 > attention 里 Rust 0.40 > 三个月前生日 0.08——可作为候选描述措辞的参考，但第一版判断走单 Choice。）

### 3.4 主体处置（谁来决定的第二半：处置）

【约束，Human 确认】

- after-chat **不等于开口**：可以接一句、可以私下做点事（整理/探索/记一笔）、也可以什么都不做。开口只是其中一种。
- **置信度是信号不是闸门**：哪怕 jev 高置信，处置权仍在主体，高置信也可选择不动。
- 代码把过阈来源整理成**一小段自然语言情境**交给主体，主体自由决定。**不给主体看 raw 分，不预设它该干嘛。**
- **【语气，Human 定 2026-09-28】** 自然地说"可能可以去……"，**不要**刻意补一句"你也可以什么都不做"——那反而显得刻意。留白靠语气（"可能可以"本身就不强迫），不靠明说。例：过 jev 门后浮出"周报框架"这条，情境写成"最近用户托付的周报框架还没做，可能可以先把它列出来"，而不是"有一件事悬着，当然你也可以不管"。

## 4. 端到端一条路径（第一个探针的形状）

```
一条真回复发出 + 无新人类输入（turn-stopping + lastEventTime 判停）
  → 攒候选：最近对话(还原 user + message.text) + attention + threads index
  → 一次 jev 调用：单 Choice（候选各一项 + none）
      choice=none 胜出 → 结束，零主模型调用
      非 none → 按 Choice 置信三档：
          高 → 浮选中那一件
          中 → 浮前几名
          低 → 当作没把握，倾向安静
  → 过阈时把浮出来源整理成一小段情境交给主体（无 raw 分）
  → 主体自由处置：接一句 / 私下做事 / 放过
```

## 5. 开放问题（往下收敛用）

- **【开放】** session "最近对话"提取的具体规则（轮数 / 字符上限），需看真实 session 定。
- **【开放】** 闸门阈值、Choice 三档分界，需真实中文对话样例回归。
- **【开放】** 闸门"反话痨"措辞会不会压过头——回归时一并校。
- **【开放】** 情境交给主体的确切格式（几件、每件多长、怎么措辞才不引导主体）。
- **【开放·更大主动】** 延后唤醒需要的定时/唤醒源；pulse 的节律与随机性；机会识别。这些是本骨架往外延伸的方向，第一探针不碰。
