# 04 — 逐条年龄摆到眼前：纯观测，不改行为

**What to build:** 主体每轮看到的 attention（以及 threads index）里，每一条后面多一个派生的年龄标记——`(14 天未动)`。它继续照原样整文件覆写，什么都不用填；harness 从 git blame 算出每条多久没被改过并在投影时挂上。**这一片不唤醒任何东西、不改变任何行为**，只增加它看得见的一个维度。

**What this answers:** 整条主动性路线上最不确定的一环——**它拿到时间维度会不会用**。会用（开始催、开始降级、开始删陈旧条目），后面做基于衰老的唤醒才有意义；不用，则"衰老可叫醒它"这个假设被否决，省掉后面全部工程。成本接近零，却能否决下游。

**Blocked by:** 03（逐条年龄来自 git blame，没有仓库就没有数据）

**Status:** complete — 实现侧 在分支 `feat/proactivity-workspace-history`（`ff93e33`）实现，收敛侧 独立重验（replay 13/24 天、邻居行缺陷已修、双回退与预算截断各有测试）。未合并，等 Human 定合并/重启。另：回填 mtime 与否 Human 未定，收敛侧 建议不回填。

## 为什么是这个形状

已验证事实（2026-10-09）：主体的 attention 现有 6 条，**0 条带 horizon**，而 `src/resident-context/scaffold.ts` 与 `src/orientation/index.ts` 两处都要求每条带 horizon。

归因很重要，因为它决定这张票的形状：**不是"没后果所以不写"，而是整文件覆写下它手写的时间无处可存**——下一次覆写就没了。所以解法不是再要求它填一个字段（会重演 horizon 的命运），而是**harness 派生、它零参与**。

同样已验证：6 条的下一步**全部卡在人身上**（"等他选/等他叫/等他拍/等他重启/他没定"）。这不是性格，是物理约束的投影——当前唯一能叫醒它的外部事件就是人说话。所以这 6 条其实是 6 个潜在的超时信号，而超时是纯时间就能产生的理由，不需要世界观察者。

## 决策要点（内联）

- **数据来源**：`git blame` 逐行最后改动时间。**已核实（2026-10-09）：主体写 attention 时每条正好是一整行**（很长的一行，条目间以空行分隔，个别相邻无空行）。所以**逐行 blame 就是逐条 blame**，不需要分块启发式——这是这张票能做到"零解析契约"的关键前提。若将来它改成多行条目，退化规则为"取块内最新行"。
- **落点**：`src/resident-context/projection.ts` 第 88 行——读 attention 的那一个 provider。读出来之后按行挂年龄，blame 模块放哪跟着票 03 的落点走（新插件自带，或并入 resident-context）。仓库不存在 / blame 失败 → 整段原样返回，当这事没发生过。
- **零手填、零新格式、零解析契约**。它写的还是自由 Markdown，harness 只在投影时附加。它改写行文（哪怕只动一个字）就视为该条被碰过——这是正确语义：改了说明它还在想这件事。
- **只做投影侧**，不碰写入侧，不加工具，不加提示要求它必须处理陈旧条目。要观察的恰恰是"没人要求时它会不会自己用"——加了提示这次观测就废了。
- **预算逻辑不动**：`materialText`（projection.ts 第 98–104 行）一行不改，标记自然计入 attention 的 8 KiB 上限——超了就截，和材料一个待遇，不绕过预算。
- **threads index 同样处理**（它的 mtime 是 10-01，比 attention 更可能有陈旧线）。
- **不做阈值、不做高亮、不做排序。** 只给事实。什么算"太久"是它的判断，不是 harness 的。
- **测试**：`tests/resident-context.spec.ts` 加三条——有年龄时挂标记、退化时原样、超预算时截断不断。

## 观测方式（这张票的真正交付物）

上线后看接下来若干真实回合里，它对这个维度做了什么。三种结果都是有效答案：

- **开始用**（催人、降级、删条、改写）→ 下游（kind 解锁 + pulse）值得做。
- **看见但不动** → 说明"可见"不够，需要的是唤醒而不是可见性；下游形状要改。
- **完全无视** → "衰老可叫醒它"假设否决，主动性应转向世界观察者（订阅/check）那条路。

结论写回 `../README.md` 的前沿，并决定是否开 kind 解锁那张票。

## Acceptance criteria

- [ ] attention 每条投影时带派生年龄标记；主体侧零新增要求（无工具、无提示、无格式约束）。
- [ ] 年龄取自 git blame，按条目块内最新改动行计算；有测试覆盖"整文件覆写只改一条"时其余条目年龄不变。
- [ ] threads index 同样带年龄标记。
- [ ] 标记计入既有投影预算，超预算时按既有 `applyBudget` 行为截断，不绕过预算、不挤掉材料优先级。
- [ ] git 仓库不可用或 blame 失败时，投影退化为"无年龄标记"的原样材料，不报错、不阻塞回合。
- [ ] 本票**不包含**任何唤醒、任何 jev 调用、任何行为变更——负例检查：不新增触发源、不改 `deliver`。
