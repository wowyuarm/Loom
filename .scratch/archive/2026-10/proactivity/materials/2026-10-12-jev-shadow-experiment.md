# Jev pulse：离线对照与真实服务实验

**日期**：2026-10-12  
**范围**：合成中文情境调用真实 Jev；真实部署历史仅在本地只读分析；锁定 DSH 的离线竞争实验。  
**授权**：Human 已允许 `source=self` 并授权实验。本轮不改产品源码、不派发实现、不启动长期 shadow 服务、不向部署中的主体 `steer`。  
**基线**：[系统研究](2026-10-12-systematic-research.md)与[DESIGN §9](../DESIGN.md)。

## 1. 结论

**保留“活动锚定 + Jev 二元门控 + 主体自由处置”的方向，但实验尚不足以确定 pulse 的问题措辞、阈值或长期效果。**

1. **Jev 能识别不依赖人类请求、也没有新外部事件的私人工作入口。** 因此不应把“有新变化”做成所有 pulse 的必要条件。
2. **上次主体处置是重要事实。** 同一个旧入口，在“还没看过”和“看过后决定等待或放下”之间，应得到不同判断；文件没改不能代表主体没处理，Jev 判 quiet 也不能代表主体已经处理。
3. **仅靠提示词不能解决输入缺失。** 时间比较、关键事实截断、旧 attention 与当前结果冲突，都会改变判断。增加规则会减少一类错误，同时漏掉另一类入口。
4. **真人优先不能只在返回结果后检查。** 当前 DSH maintenance 不因人类输入自动结束；输入会等待任务释放。未来 pulse 应及时取消自己的 Jev 调用，并处理尚未接纳的旧 notice。
5. **不直接继承 after-interaction 的 `P(quiet) < 0.4`。** 本轮分数对问题措辞、选项顺序和输入组织有可观察的敏感性；低调用费用不是可靠性的证据。

本轮得到的是可复查的故障与边界证据，不是线上主动性验收。

## 2. 方法与记录

### 2.1 固定条件

- 使用已安装的 `@wowyuarm/dsh-jev@0.1.1` 服务，官方 endpoint，固定 `jev-1.13.0`；所有成功响应均核对了返回模型版本。
- DSH 与 agent-loop 均为 `0.2.0-rc.2`；没有升级依赖。
- 已有部署凭据只读入进程，不写入实验文件、命令或日志；没有保存 Human 提供的凭据。
- 发给 Jev 的是合成中文材料，没有真实人名、会话、workspace 原文、路由或私人路径。
- 一次请求只尝试一次，单次超时 15 秒、调用总取消边界 18 秒。失败立即停下，后续由实验者显式继续。

### 2.2 情境与对照

主实验预先构造 36 个情境：14 组成对情境、8 个边界情境。34 个有作者预期标签，`attend` / `quiet` 各 17 个；2 个材料不足的情境标为 `unknown`。预期标签不发送给模型，也不等于 Human 或真实主体的判断。

| 对照 | 内容 |
| --- | --- |
| state | 仅内容；内容 + 时间；内容 + 时间 + 上次检查与处置事实 |
| open 问题 | 简短询问是否值得醒来；明确醒来不要求行动或发消息 |
| evidence 问题 | 额外区分等待、已完成、旧材料、自主工作、之前 quiet 与主体处置 |
| 复测 | 12 个诊断情境各重复 3 次；单问题调用并交换两种选项顺序 |
| 输入覆盖 | 重要观察放头部或尾部，对照完整材料与 2,000 字符前缀 |
| 新情境 | 12 个后续情境，包含私人工作、等待授权、到期安排、旧记录与材料不足 |
| 探索性追加 | 中文短问题、结构化事实、Noul 与 Choice 对照；另修正一个情境的矛盾时钟 |

主实验共 108 次请求。探索性追加是在看到主实验结果后设计，不能当作独立验证集。所谓“新情境”也是同一实验作者编写，规模很小，不能据此报告产品准确率。

### 2.3 调用结果

| 项目 | 结果 |
| --- | --- |
| 成功请求 | 259 次，472 个问题答案 |
| 失败 | 1 次 `transport`；原因未查明；停止后显式继续成功 |
| input / output tokens | 205,476 / 14,840 |
| 延迟 | 中位数 314 ms；本批第 95 百分位 498 ms；最大 1,760 ms |
| 估算费用 | 按官方当日 $0.042 / 百万 input tokens，约 $0.00863；不是账单金额，未计失败请求可能产生的费用 |
| 响应检查 | 版本一致；Choice 概率合法且和为 1；Noul 在 0–1 内 |

这是低并发的一次实验，不能推出服务长期可用率、生产延迟或任何免费保证。第一次 transport 失败发生在失败文件记录功能加入前，只保留了工具输出中的安全分类；不能伪称有完整逐次失败日志。

脚本、请求、结果和汇总保存在 `.scratch/local/proactivity-20261012/`（gitignored）。关键文件为 `cases.mjs`、`run-jev.mjs`、`sweep-results.jsonl`、各追加实验的 `*-results.jsonl`、`SUMMARY.json`。真实历史结构化结果也仅保存在本地。仓库只保留本报告，不复制私人原文或运行日志。

## 3. Jev 判断结果

### 3.1 自主工作不需要新事件

完整反馈 state 下：

| 情境 | 预期 | open 的 P(quiet) | evidence 的 P(quiet) |
| --- | --- | --- | --- |
| 自选研究，两篇已读，第三篇可读且未读 | attend | 0.10 | 0.09 |
| 当前比较完成，扩大范围需用户许可，用户说暂不推进 | quiet | 0.71 | 0.90 |
| 私人证据可核对，明确不需要对外发消息 | attend | 0.05 | 0.10 |
| 用户要求先不催，但原先缺失的资料刚发布 | attend | 0.04 | 0.01 |

这支持“醒来不等于开口”和 self-source 的可行性，但只证明模型能识别这些明确合成情境，没有证明真实主体会持续留下同样清楚的材料。

### 3.2 上次处置有效，但不会自动消除重复唤醒

完整反馈 state 下：

| 情境 | open 的 P(quiet) | evidence 的 P(quiet) |
| --- | --- | --- |
| 同一比较入口，只有前次 Jev quiet，主体没读过 | 0.26 | 0.39 |
| 同一比较入口，主体读过后判断无意义并放下 | 0.79 | 0.92 |
| 原入口可读，但主体上次确认缺一份未公开资料 | 0.26 | 0.52 |
| 只能等用户的材料，14 天没改 | 0.23 | 0.87 |
| attention 仍写未完成，当前产物说明已完成并核验 | 0.14 | 0.51 |

结果支持记录“上次主体实际做了什么”，不能只记录 Jev 的分数或文件变化。

但 evidence 问题也漏掉了若干作者预期应该醒来的情境：到期核查 `0.74`、新进程结果可读 `0.57`、尚未回应的关系情境 `0.47`。这说明提示词变保守不是单向改进，更不是可以直接上线的修复。

### 3.3 阈值对照不是准确率校准

以历史阈值 `P(quiet) < 0.4` 比较主实验 34 个有标签情境：

| state | open：不该醒却醒 / 应醒未醒 | evidence：不该醒却醒 / 应醒未醒 |
| --- | --- | --- |
| 内容 | 5 / 1 | 2 / 3 |
| 内容 + 时间 | 5 / 0 | 1 / 4 |
| 内容 + 时间 + 反馈 | 4 / 0 | 0 / 3 |

**不能将此表解读为增加反馈提升了准确率。** 内容版本有 3 对相同输入却被赋予相反标签；时间版本仍有 2 对，因为决定标签的事实被有意移除了。移除这些不可区分的情境后，样本数量分别为 28、30、34，仍不是相同信息条件下的公平比较。

这项对照的确定结论是：**缺少时间和先前处置时，有些情境根本无法区分，不能要求模型从缺失事实中作正确判断。**

后续 12 个新情境中，1 个没有预期标签，另 1 个“凌晨私人工作”与结构化下午时钟矛盾，排除后只剩 10 个有效标签。open / evidence 在这 10 个情境上均与作者标签一致；样本太少，且由同一作者编写，不能推定泛化。修正时钟后重新调用，凌晨私人工作仍未通过 `0.4`，而主实验的另一组凌晨私人工作通过，说明措辞与情境组织仍需核对。

### 3.4 重复、顺序与问题类型

- 12 个情境各重复 3 次，与主实验该情境合计 4 次观察：open 最大分数跨度 0.10，evidence 为 0.15；两种问题各有 1 个情境跨过 `0.4`。
- 单问题调用并交换选项顺序：open 最大变化 0.10；evidence 最大变化 0.25，12 个情境中 2 个跨过 `0.4`。每个顺序只调用一次，观察差异同时包含随机波动，不能全归因于顺序。
- 改成短中文问题后，一些关系和到期情境改善，但旧完成材料仍可能唤醒；没有出现对所有情境都更好的问法。
- Noul 能表达同一个二元问题，官方也将它推荐用于 yes/no。然而同样措辞下，本次 Noul 与 Choice 的概率明显不同；此前 10 个有效新情境中，以 `P(attend) > 0.6` 对照，两种类型都漏掉了资料核对和私人阅读。不能把类型切换当作解决准确性问题，也不能把阈值无验证地搬过去。

因此本轮不选择新阈值，不通过反复改词把同一小样本调到全对。

## 4. 输入边界：比多写提示词更需要处理

### 4.1 到期比较不应交给 Jev

合成情境“16:00 核查，现为 16:05”在 evidence 问题下得到 `P(quiet)=0.74`。改为明确的结构化事实（安排、当前时间、`due: true`、尚未核查），同一问题得到 `0.19`。

官方 [Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13) 明确说明日期比较和数值计算不可靠，应在代码中计算。实验与这个版本说明一致。

这不授权解析自由文本承诺。只有来源已明确表达且可验证的时间安排，未来才可计算到期事实；自然语言旧笔记不能自动变成现行安排。对 slice 1，则机械计算活动间隔，把语义判断留给 Jev。

### 4.2 2,000 字符前缀会漏掉尾部事实

同一批完成记录里加入“缺失资料刚发布，现在可以继续自己的研究”：

| 重要事实位置 | 输入 | open 的 P(quiet) | evidence 的 P(quiet) |
| --- | --- | --- | --- |
| 头部 | 2,000 字符前缀 | 0.20 | 0.49 |
| 头部 | 全文 | 0.21 | 0.52 |
| 尾部 | 2,000 字符前缀 | 0.94 | 1.00 |
| 尾部 | 全文 | 0.24 | 0.41 |

截断情境使用的是无补充字符的中文文本。当时 after-interaction 的上限实际是每份材料 **2,000 UTF-16 code units**（其实现后被 pulse 取代，见 `src/pulse/state.ts`），不是 token 上限。

本地只读检查某部署当时的原始 attention：2,938 code units、10 个列表项开头，前缀只保留 6 个列表项开头；threads 为 1,291。这个计数不等于完整关注事项计数，但已经证明当前输入可能截断正常材料，而不是仅防止极端膨胀。未证明这次截断导致了某个历史错误。

未来 pulse 需要明确预算与完整性，不能把截断后的“没有入口”当作全文结论，也不能仅取 git dirty 的行：没有新修改的私人阅读线仍可能有效。官方 1.13 的 `state + 最长问题` 上限为 32k tokens、总请求为 64k；本实验没有接近或压测这些 token 上限。

### 4.3 结构化事实有帮助，但不是语义处置器

在诊断样本中，明确上次等待原因或进程结果让 evidence 分数从 `0.47` 变成 `0.99`、从 `0.68` 变成 `0.02`。但“attention 未同步、当前结果已完成”结构化后反而从 `0.53` 变为 `0.19`，错误地倾向唤醒。

不能据此让 Harness 从自由文本里生成“是否有价值”“是否完成”判断，再让 Jev 重复判断。可由机器稳定获得的是时间、来源、是否有主体回合、工具与投递结果、材料是否变化；主体放下某件事的理由仍需来自主体留下的证据。

## 5. 真实历史：确认执行结果，不伪造反事实

### 5.1 43 次判断与 9 次主体处置

沿用系统研究的固定 journald 窗口，核对 43 次判断与 Session 中 9 个 notice，判断到 notice 的间隔为 15–80 ms。

| 结果 | 数量 | 可解释范围 |
| --- | --- | --- |
| 完成，无工具调用 | 3 | 被叫醒后安静结束是真实可达的结果 |
| 完成，有 `message` 调用且工具成功返回 | 5 | 证明发送工具成功，不代表人已读或认可 |
| 有私人工具调用，最后模型错误 | 1 | 主体执行可能失败，不能把唤醒当作完成 |

5 个发消息回合中，1 个在回合中途收到新的人类输入，且发送发生在人类输入之后。**不能把这条回复完全归因于主动唤醒。** 其余 4 个发消息回合在结束前没有新的真人输入。部分回合也有文件编辑或研究工具调用。

3 个安静回合不能标成 Jev 的假阳性：本设计允许主体醒来后否决。历史也没有足够独立标签来判定 34 个 quiet 是否错过了价值，或收到消息的人是否感到被打扰；后续真人消息的时间不是满意度证据。

### 5.2 不能精确重建 43 份原始 Jev state

日志记录概率、姿态与交付，没有记录完整 Jev 请求。runtime-context 是主体回合的快照，而 after-interaction 在之后另读 workspace；最近快照早于判断约 4.5 分钟至 829.7 分钟，不可当作精确判定输入。

workspace Git 的首份提交为 2026-10-09 11:20:18（UTC+8）。43 次判断中 33 次在此之前；之后 10 次可以利用 Git 增强重建，但提交也不是文件每次修改的记录，且可能包含多个文件改动。因此本轮没有把近似快照伪装成原始请求，没有把 43 条当作可直接重放的真实校准集，更没有把真实私人材料发给 Jev。

## 6. DSH 竞争与活动时间线

### 6.1 maintenance 保持互斥，但不自动让真人立即开始

对锁定的 DSH agent-loop 使用无网络的 mock 模型：

- maintenance 人工延迟 400 ms，人类输入在约 35 ms 时入队；未主动取消时，输入到模型请求仍等待约 **370 ms**。
- 监听同一个 Agent 的 `agent/inbox/inserted`，在人类输入时取消实验任务；输入到模型请求约 **1.7 ms**。
- maintenance 期间公开 `agent.status` 仍为 `idle`，第二个 `runMaintenance()` 被拒绝。不能只凭公开 idle 判断真正空闲。
- pulse notice 与真人输入都在 maintenance 内排队，不移除旧 notice 时，两者会一起到模型；按该 notice 的 id 移除后，模型只收到真人输入。
- 单独通过已安装 Jev 服务的离线 transport 验证：组合取消信号传到底层，返回 `cancelled`，即使配置 3 次尝试也只执行 1 次。

这些数字只说明该离线竞争机制，不是生产延迟承诺。源码依据是锁定 `dsh-agent-loop` 的 `runMaintenance()` 与 wake latch；当时的 after-interaction（后被 pulse 取代，见 `src/pulse/index.ts`）在 Jev 返回后重新检查输入，但没有在人类入队时主动取消调用。

未来 pulse 的安全路径应是：新输入使当前评估失效并取消；Jev 返回后仍重查时效；旧 pulse 如果尚在 inbox，按自身消息 id 移除，不能清空真人消息。notice 已被接纳后，人类输入继续走 DSH 安全 step 边界，不能为了取消 pulse 中断主体工具。

### 6.2 一条活动时间线不等于无需记录检查时刻

离线时间模型验证了：

1. 人类回合在第 29 分钟结束，30 分钟静默窗口应在第 59 分钟到期，不是墙上第 30 分钟。
2. 私人回合在第 95 分钟结束，同样使下一检查推到第 125 分钟。
3. Jev quiet 没有主体回合，不应更新“主体最后活动”；否则它自己会伪造主体仍在活动的事实。
4. 仅用 `lastActivity + window` 判断资格，quiet 后每次轮询仍符合条件；还要有“上次检查”或下一次已安排的检查事实，避免密集重复调用。这不是给主体加配额，也不必为交互与主动性各造一条活动时钟。
5. 长时间停机后只做一次当前检查，不追补每个漏掉的心跳；长工具回合期间不并发开另一段主体活动。

模型中分别用 `lastActivity` 与 `lastCheck` 实现上述区别，重启测试只模拟这些事实被正确恢复。**这不是已经完成持久化测试，也没有验证系统时钟跳变。** 真实存储归属、generation 换代与失败退避仍需实施合同和验证。

## 7. 对 DESIGN §9 的建议与边界

### 保留

- 一条活动时间线；人类交互与私人回合都是真实活动。
- self-source 已获 Human 确认；没有新事件仍可有自己的连续工作。
- 二元门控只决定是否唤醒；不决定说、做、执行任务或维护哪些材料。
- pulse 内部 `steer` 不要求先泛化 `deliver`；来源扩展跟随具体能力。
- 不预建通用 Inbox，不恢复 legacy 的多认知器官，不用每日次数替代处置反馈。

### 实施前需要补足

| 问题 | 建议 |
| --- | --- |
| 旧材料重复成为理由 | 让门控与主体看见实际处置证据，区分 Jev quiet、主体未做、主体做完与主体放下 |
| quiet 后再次检查 | 记录检查时刻或等价调度事实，不篡改主体活动时间 |
| 真人到达时调用仍持锁 | 当前 pulse 单独取消，并保留返回后时效检查；旧 queued notice 只删自身 |
| 时间与材料覆盖 | 间隔由代码算；预算与截断显式可见；不得伪装成全文结论 |
| 固定阈值和问法 | 使用新的真实标注场景核验，不复用三档 0.4 的“已校准”说法 |

另有一处未收敛：DESIGN §9.3 写客观变化不需要 Jev，§9.6 又写队列非空问 Jev“现在动哪条”。本轮没有实验事件队列或行动排序，不据此替 Human 选择；slice 1 不需要解决这个问题。

## 8. 下一份有效证据

本轮不继续无限改写合成情境。下一份有价值的证据是**真实活动时间线下的长期影子记录**，而不是更多同一作者写的高分样本：

- 不向主体 steer，观察长时间无人输入、真人交互、私人回合结束、旧线无变化、重启与截断。
- 记录完整且有隐私边界的输入证据，才有资格复查每次判断；明示近似重建。
- 对“等待”“已放下”“尚未看过”“没有外部新事件但有私人入口”分别检查，不能只统计 attend 数量。
- 把值得醒来的判断与是否对外发消息分开验收；安静处置不是失败。

该长期任务及之后的真实唤醒未在本轮实施，也没有部署或派发授权。当前可以确认的是：小型执行边界可复用，主要未验证风险在输入事实与语义门控，不在是否能调用定时器。
