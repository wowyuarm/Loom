## 0. 这一片是什么、边界在哪

- **只做 after-chat"就地接续"**：主体刚回完话、还醒着（idle），代码判"这段对话真的停了"后，用一次 jev 判断此刻该不该主动、以什么姿态主动，把结果整理成一小段自然语言情境交给主体自由处置。
- **明确不碰**："延后唤醒"那一半——需要**持久**唤醒源（几小时后才响、跨进程重启仍在、脉冲节律、机会识别）。留给更大的主动。
- **为什么先做它**：after-chat 是更大主动性的最小缩影，同一套骨架（何时醒 / 看什么 / 谁决定 / 怎么防过度）复用；且最安全——主体本来就醒着，不需要新唤醒基建，判断错顶多多说一句。
- **硬前提**：真实中文对话上的校准。手造场景只能证明机制成立，阈值与体感只有真跑起来才知道。

## 1. jev 的角色（守住"只提议不决定"）

- jev 是"System One"快模型，不生成文字，只对一个 `state` 评估结构化问题、返回结构化答案。约 70–500ms、极便宜（约 ¥0.0001/次）。
- **jev 只提议信号、绝不改状态；主体永远看不到 jev 的 raw 打分。** 代码在概率上门控，只把整理好的情境交给主体。
- 接入：OpenRouter `POST /api/alpha/decisions`，model `typesafe/jev-1.13`，native TypeSafe schema（非聊天端点）。Choice 的选项字段名是 `criteria`（对象 `{key: 描述}`）。
- 约束：中文非 jev 主训练语言；任何阈值必须在真实中文对话上回归验证过才可信。

## 2. 判断：一次调用、一个 Choice、三档动作

**一次 jev 调用、一个 Choice**，选项是**固定的三档动作类型**（不是动态拼的每条活线）：

| 动作 | 含义 |
| --- | --- |
| `quiet` | 什么都不做，安静。**预期的多数。** |
| `speak` | 开口——另起一个他会在意的话题 / 之前聊到觉得值得再说一句 / 关切。具体说什么交主体。 |
| `act` | 不必开口、去做一件事——一般来自过往交流 + attention/threads，或一个明确"该马上做"的信号。具体做什么交主体。 |

**为什么是三档、不是五个动作**：实验证明 jev 只能稳分"做 vs 不做"两极；`continue/raise/flag` 这类细腻社交姿态即便在为它们量身造的场景里也几乎不胜出，且每加一个选项都摊薄概率、反而害了该唤醒的场景。三档粒度粗、语义拉得开、jev 挑得动。"具体说什么/做什么"本就该是主体（System 2）的活。

**唤醒判据（核心规则，主体看不到 raw 分）**：

> 锚在 **`quiet` 的概率**，不是锚在胜出项的概率。
> - `P(quiet) < 0.4` → **唤醒**，取 speak/act 里概率高者作为姿态。
> - `P(quiet) ≥ 0.4` → **安静**，不唤醒主体（零主模型成本）。

（为什么锚 quiet：五选项下概率被摊薄，"胜出项 > 0.7"会把该唤醒的场景压死；而"安静"这一极 jev 判得最稳，收尾场景能顶到 0.9。三档下同理，锚 quiet 最稳。）

**问题/选项措辞是最要紧的参数**：候选描述锚在"有没有具体活线/明确留下的事"，别用"现在开口合不合适"这种社交感受（后者在该接/不该接场景都给 ~0.65，不区分）。指令里加"不要因为想显得关心就倾向开口"以压话痨偏向。措辞与 0.4 分界都待真实中文回归微调。

## 3. 骨架四块

### 3.1 何时醒 —— 一次性静默计时器

- 挂点：**只有"人类输入引发的 idle"才挂闹钟**——主动回合自己结束产生的 idle **绝不挂**（否则自触发死循环，见 §4a①）。DSH 有 `agent/turn-stopping` 边界（模型这回合无待回内容、要提交时触发），channels 已骑它做"回复写了没发出去"的追问；after-chat 挂同一类边界。
- 计时：对话一停，挂一个 `random(3–14min)` 的**一次性**闹钟。**纯插件本地、不跨重启、无人时不长期空转、响过不自动重挂。**
- 判"真停了"：现成信号——time-context 投影一直记 `lastEventTime`（最后一个模型可见事件时间），距上次多久已每轮注入。
- 延迟本身有用：立刻接会撞上他还在打字；等几分钟静默才算"真停"，随机化去掉整分钟敲门的机械感。
- **与持久唤醒源的边界**：这是一次性、只活在这次静默里的计时器；持久唤醒源（几小时后响、跨重启、脉冲节律）不在本片。

### 3.2 醒来看什么 —— state 的三块材料

优先级（Human 确认）：**最近对话首要**，然后 attention，然后 threads index。三源原文直接进 jev 的 `state` 作背景（因为 jev 只挑动作姿态、不在候选串里挑，无需把它们归一化成干净选项——这就是三档动作模型顺手化解的"候选构造"难题）。

- **最近对话**（首要，需从 session 事件拼）：
  - 对外真说出去的是 `message` 工具的 `text` 参数（普通 assistant 文本谁都收不到）；用户侧是 user 消息。两者都抓。
  - 提取规则（看过三条真实 session）：**按轮数截，不按字符平均截**——人类侧整条留（真实人类消息多为 5–25 字一句），Loom 侧每条截首段/前 ~150 字（活线信号几乎全在人类的话里）。
  - **剥来源前缀**：真实人类内容形如 `[<channel> · direct · from <人名>]\n<正文>`，第一行是通道元信息，喂 jev 前去掉。
  - **过滤 runtime-context 快照**：`user/message` 里 `source.kind='runtime-context'`（form='snapshot'）是注入的上下文、不是人说的话，会污染"最近对话"。只取 `source.kind='user'`。
  - 切片粒度：最近 1–3 轮 human↔loom 往返（一轮 = turn/start…turn/end）。确切轮数、Loom 侧截断长度与阈值一起在真实回归里微调。
- **attention**：`attention/attention.md` 常驻内容。
- **threads index**：`threads/index.md` 里休眠的活线（一行一条）。

### 3.3 谁决定 —— jev 提议、代码门控、主体处置

- jev 提议（§2）。代码按 `P(quiet) < 0.4` 门控（§2）。主体最终处置（§3.4）。
- **代码闸门在 jev 前、jev 看不到**。保守全在代码，不写进 jev 指令（否则和 jev 校准打架）。
- **第一片不设冷却、不设次数上限（Human 决定，效果优先）**。只保留结构性的"一次对话停顿至多一次检查"——这个必须留，否则后台空转。
  - **为什么先不设也不会失控**：闹钟只在对话停下时挂、响过不自动重挂 → 只有他真的回了、产生新停顿，才有下一次检查；他不理就没有下一次。且收尾场景 jev 自返回 quiet 高（对话往"聊完"走时下一次 after-chat 会自己安静）。真正的"循环"只发生在他每次都实质接话、话题真的一直活着——那本就是该继续的对话，不是骚扰。
  - **冷却（曾定 30min）+ 次数上限是已知旋钮**，留作"真观察到黏人循环再加"，不预先拧。
- "他忙不忙"第一片不单独造信号，用"静默够久"近似（闹钟能响本身说明这几分钟没动静）。

### 3.4 主体怎么处置

- after-chat **不等于开口**：可以接一句、可以私下做点事、也可以什么都不做。
- 姿态（speak/act）不写进 prompt 当指令，**只用来塑形那段情境的语气**：`speak` → "……可能可以跟他说一句"；`act` → "……可能可以先把它做了"。
- 代码把过阈来源整理成**一小段自然语言情境**交给主体，**不给 raw 分、不预设它该干嘛**。
- **语气**：自然说"可能可以去……"，不刻意补"你也可以什么都不做"（反显刻意）。留白靠语气不靠明说。例：过门后浮出"周报框架"，写成"最近用户托付的周报框架还没做，可能可以先把它列出来"。

## 4. 并发模型（真人消息永远压过主动检查）

现状：channels 入站走 `agentRuntime.deliver()` = `agent.followup()`，开一个独立新回合。主动这条路（乃至入站消息）改成**在下个 step 边界插入**更对——不打断正跑的 tool call，不另起竞争回合。

| 情况 | 处理 |
| --- | --- |
| 闹钟未响他先发消息 | 取消待响闹钟，正常反应式回合回他，这轮再停下才挂新闹钟 |
| 检查进行中他发消息 | jev 检查跑成 `agent.runMaintenance`（从 idle 起的非回合任务，其间进 inbox 的输入停着不丢）；检查完若要醒但 inbox 已有他的消息 → 放弃主动、让位。若主动回合已在组话你才发 → 你的消息按 steer 在下个 step 边界（当前 tool call 结束后）插入，模型转去回你 |
| 检查后（回合已结束）他发消息 | 普通反应式回合，无特殊处理 |

**落地待定细节**：steer 语义比 followup"软"（step 被拒 / agent 被弃时 steer 可能被丢弃），到底用 `agent.steer` 还是带 target 的 `agent.send(msg, target, wakeup)`，须在实现时对着 DSH 语义敲定。方向确定：别另起竞争回合、在下个安全边界插入。

**连续性钩子**：主动回合发出的内容标一个自己的 `source`，让 continuity host 的 `isEphemeralNotice`（已为主动性预留此钩子，v1 默认返 false）在换代时"重新推导而非重读"它。

## 4a. 边界情况补全（2026-09-29 复核，Human 要求再想）

**① 挂钟铁律（最要命的一条，必须写死）：只有"人类输入引发的 idle"才挂闹钟，主动回合自己结束产生的 idle 绝不挂。**
否则：主动回合结束 → 进 idle → 又挂闹钟 → 到点又检查 → 又唤醒……**自我触发的死循环**。判据不能是"进了 idle"，必须是"这次 idle 的前因是人类消息"。第一片必须有一条测试专门盯它（主动回合的 idle 不挂钟、不产生下一次检查）。

**② 到点先验 idle：** `runMaintenance` 在已有回合/维护任务占用 agent 时会**同步抛出**。所以闹钟到点先看状态：不在 idle（长 tool call、后台任务、他的新回合刚起）→ **放弃这次检查、不重挂**（说明这段并没有真的停下）。统一不变量：**同时最多一个闹钟**；重挂必先取消上一个；检查在飞时不接受新闹钟。

**③ 交付前的时效复核：** 从"取 state 快照 → jev 调用（百毫秒到数秒）→ 组织情境 → 插入"之间有窗口，他可能已开口。**插入前复核：若最新人类输入晚于快照时刻 → 放弃本次主动**。否则会出现"他刚说了新话题，Loom 却按几秒前的旧判断插一句"。

**④ jev 失败一律 fail-closed：** 网络/5xx/SSL 中断在真实调用里出现过（520、`UNEXPECTED_EOF_WHILE_READING`）。失败 = 当作 quiet（不唤醒），**有界重试（少量带退避）后放弃，绝不无限重试、绝不阻塞**。概率字段缺失/非法同样 fail-closed。

**⑤ 深夜问题（最可能真实发生的扰民）：** 闹钟能在凌晨三点响，现设计没有任何东西挡它。**倾向：把本地时刻 + 距上次互动多久写进 jev 的 state，让它自己权衡**（不加硬规则）；"静默时段"作为**已知旋钮**留着——真被半夜吵到再加。这条要 Human 拍。

**⑥ 源缺失要降级，不要炸：** attention.md / threads index 不存在或为空 → 只用最近对话照跑；**全新会话、尚无对话可续 → 直接跳过检查**（没有"过去"可主动，也省一次调用）。

**⑦ 进程重启 / 换代：** 闹钟在内存且随 fiber 释放 → **重启即丢，可接受**（漏一次主动无害，不补跑）；rollover 换代时旧句柄失效 → 放弃本次检查，等下一次人类输入引发的 idle 再挂。

**⑧ 主动结果发去哪里：** 发到"这次停顿所在的那个会话/路由"（channels 的 focus 即最近一次已送达入站的路由），不要漂到别的通道。

**⑨ 另有个现成兜底，不用额外做：** 主动回合若写了文本却没调 `message` 工具发出去，channels 已有的"回复写了没发出去"追问会自动接住它。

**⑩ 计时原语用现成的：** `ctx.timeout(fn, delay)`（`@deepseek-ai/cordis-plugin-timer`，dsh-base 的 `id: timer` 行已加载），返回 disposer、随 fiber 释放——**不要用裸 `setTimeout`**，不重造。

## 4b. 接 jev 这个 model：单独一个插件（已定 2026-09-29）

**结论：要单独一个插件，但"不是"注册成 DSH 的 LLM provider/adapter。**

- **为什么不能当 llm adapter**：`ctx.llm` 的扩展点是 `LlmAdapter`——"harness 消息与流式词汇表的 provider-wire 适配器"，必须实现 `stream(options): AsyncIterable<StreamChunk>`。jev 返回的是结构化判断（choice + probabilities + confidence），**没有文字流**；塞进去等于伪造 chunk 流，是错的抽象。
- **DSH 自己已有先例，照抄即可**：`@deepseek-ai/dsh-web-search-deepseek` 就是一个"非对话的 model 调用"插件——它的模块注释写明：**wire format 与原生 fetch 客户端是 provider 私有的、不走 `ctx.llm`**；它实现 `dsh-web` 里的 `WebSearchProvider` 接口，以稳定 provider id 注册，凭据走 credentials/环境变量，端点与模型名可用环境变量覆盖。jev 走完全同构的形状。
- **【决策 2026-09-29】落点改定：不在 Loom 内，而是 dsh-plugins 仓里一个已发布包 `@wowyuarm/dsh-jev`**（Human 定；讨论在 dsh-plugins 的 dsh-plugins 仓的 jev 讨论，实现由 该包实现方 认领）。故此：
  - **接口归这个包自己**（包内声明 ctx augmentation，暴露 service，拟 key `jev`），**不放 Loom 的 `src/contracts`**——它是通用 provider，不是 Loom 的能力模块。Loom 侧只 `inject` 这个 service key、按已发布版本钉依赖（同 `dsh-context-continuity` / `dsh-channel-gateway` 一样的外部包）。
  - 包自己拥有：endpoint/model 配置、超时、有界重试、TypeSafe decisions 请求体、**凭据（配置/环境变量，绝不入库）**。
  - **必须是 service 不是 tool**：after-chat 的判断在 `runMaintenance` 里由代码发起、那时主模型没醒；工具形态会逼着把主模型叫起来，正好花掉要省的钱。
  - **依赖面：只声明真正 import 的 peer**（Human 定 2026-09-29）——不跟随整条 dsh 线，免得频繁适配。仓库既有先例：`channel-gateway` 只声明 `@deepseek-ai/cordis ^4.0.1` + `@deepseek-ai/schemastery ^3.18.1`，**一个 dsh-\* peer 都没声**；jev 包预计同样只这两个（cordis 用于 service/ctx 增强，schemastery 用于校 config）。于是它在 0.1.7 线与 0.2 线都能装，Loom 今天即可用（Loom 的 cordis 4.0.4 满足 `^4.0.1`）。**版本线因此不再是阻塞。**
  - **默认走官方 api_base**（`https://api.typesafe.ai/v1`，端点 `/systemone`），api_base 与 key 均可配置。**随 transport 变的只有 model 名这一处配置**（官方 vendor 命名 vs OpenRouter 的 `typesafe/jev-1.13`）；**criteria 的形状不随 transport 变、随 question 类型变**——`score` = 有序数组（下标=档位）、`choice` = map `{选项: 描述}`、`noul` = `criteria.true|false`（vendor 文档 2026-09-29 核），故 provider 内不做 transport 分支。**model 默认钉死版本**（如 `jev-1.13.0`）、不用 `jev-latest`：阈值是用固定模型校准的，模型漂移会静默作废整套校准。
- **为什么不塞进主动性插件**：Human 最初问的形态里还有**对话中密集介入**（mid-chat），它要的是同一个 model。两个消费方、一个归属；塞进主动性插件就会逼第二个消费方 import 它的实现（违反"插件之间不 import 彼此"），或重复实现。
- **收益**：模型可换（换家 System-One、换本地、测试用 stub）而不动消费方；端点/凭据/重试只有一处；Loom 侧不留 vendor wire 代码。

## 5. 端到端一条路径

```
一条真回复发出 + 进 idle（turn-stopping / lastEventTime 判停）
  → 挂 random(3–14min) 一次性静默闹钟
  → 他在响前发消息？ → 取消闹钟，正常回，重挂
  → 闹钟响 → 进代码闸门（结构性"一次停顿一次"；第一片无冷却/次数）
  → 攒 state：最近对话(剥前缀/滤快照/按轮截) + attention + threads index
  → 一次 jev 调用：单 Choice { quiet / speak / act }（runMaintenance）
      P(quiet) ≥ 0.4 → 安静，结束，零主模型调用
      P(quiet) < 0.4 → 取 speak/act 高者定姿态
        → 把来源整理成一小段自然语言情境（无 raw 分，语气塑形）
        → steer 在下个 step 边界交给主体
  → 主体自由处置：接一句 / 私下做事 / 放过
```

- `P(quiet) < 0.4` 分界、Choice 措辞、"不要因想显得关心就开口"是否压过头——真实中文对话回归。

- 主体拿到情境后的真实表现（会不会显得做作、会不会过度顺着 jev 姿态走）——**零真实模型回路证据**，第一观察项。
- 3–14min 延迟的体感是否合适。

## 7. 已确认决策清单（Human 拍板 2026-09-28，9–11 于 2026-09-29）

1. 只做 after-chat 就地接续；延后唤醒（持久唤醒源）延后。
2. 一次 jev 调用、一个 Choice、三档动作 `quiet / speak / act`；弃五动作、弃 Noul/Choice 两段式、弃 Score。
3. 唤醒判据锚 `P(quiet)`，初值 `< 0.4` 唤醒。
4. 触发 = 一次性 `random(3–14min)` 静默闹钟；不造持久唤醒源。
5. 代码闸门在 jev 前、jev 看不到；第一片不设冷却、不设次数上限，只留结构性"一次停顿一次"；冷却/次数作已知旋钮留待观察后加。
6. 并发：真人消息永远压过主动检查；jev 检查走 runMaintenance；插入走 steer/下个 step 边界（followup→steer）。
7. 候选优先级：最近对话 > attention > threads。

9. **挂钟前因必须是人类输入**（主动回合自己的 idle 绝不挂钟，防自触发循环）。

## 8. Loom 主动性的总体方向（2026-10-02 增补）

本节扩展主动性的总定义，不改写 §0–7 已收敛的 after-interaction 第一片。这里的整体目标与 A/B/C/D 优先级已获 Human 认同；jev 如何参与召回、Inbox 是否作为统一逻辑入口、C 的具体履行语义仍待收敛，不能直接据此派发实现。

### 8.1 目标与职责

主动性不是增加交互次数，而是在没有新直接指令时，让 Individual 仍能基于有来源的机会决定是否继续注意或行动；放弃是正常结果。Harness 提供时间、持久状态、唤醒、输入接收、前后台竞争，以及外部行动的授权、Delivery 与恢复条件。Individual 拥有身份、关系判断、是否接纳机会和最终处置。

一个机会至少需要可核对的触发事实、说明“为什么是现在”的依据和可选处置；新输入、世界变化或时效过去都可能使它失效。时间 tick 可以唤醒检查，但 tick 本身不证明有值得做的事。

主动性风险按三条轴递增：离当前人类输入的距离、行动的可见性或外部影响、证据的强弱。越远、越可见或越难撤回，就越需要持久记录、竞争检查、授权和结果对账。目标不是向更高主动级别攀升，而是在最低足够级别上产生真实价值。

### 8.2 能力分类与顺序

| 类别 | 价值来源 | 当前方向 |
| --- | --- | --- |
| A. 同回合关联接续 | 主体已醒且相关材料已经进入当前上下文 | 先用不额外调用 jev 的主模型基线评估；暂不默认新增 Harness 能力。 |
| B. 对话停顿后的接续 | 刚发生过的交流与其尚存的关联线 | 现有 after-interaction 继续观察，交由 体验侧 评估真实体感。 |
| C. 明确托付的未来履行 | Individual 明确委托、且有未来时点或条件的事项 | 下一项正式 Harness 主动性候选。 |
| D. 无明确托付的机会回看 | 节律触发后从 attention、threads 或变化材料中发现的候选 | 放在 A/B/C 有效果证据之后；不以增加聊天为目标。 |

A 中，如果相关材料尚未进入上下文，问题可能是 Harness 召回和上下文质量，而不只是主模型是否会接话。只有观测到明确的召回遗漏，才评估 jev 是否改善材料选择；不把它默认插入每条已醒着的正常回合。

### 8.3 Input 与 Inbox 的讨论模型

当前讨论的 Inbox 模型是：Harness 通过一个输入入口让同一个 Individual 接触外界与自己的未来安排。来源可以是人的消息、已订阅服务返回的事件、Individual 留给未来自己的明确托付。收到 Input 后是否形成机会、是否唤醒主体和如何处置，仍由 Individual 决定。

这里的 Inbox 暂指逻辑上的输入接纳入口，不承诺所有来源共用同一张物理队列表。外部订阅的注册是 Effect，服务返回的变化是 Input；未来托付到期后产生的 Input 也不等于已经完成该托付。

DSH 当前 `Agent.inbox` 是按 Session 日志恢复的 `next-turn` / `next-step` 待处理消息队列，能够保存尚未消费的 Agent 输入，但它本身不负责服务订阅、承诺的期限与取消、机会判断或到期唤醒。二者不能只因同名就视为同一产品能力。

### 8.4 jev 与上下文召回

jev 只对本次调用提供的 `state` 做结构化判断；它没有跨调用记忆，不搜索 Session、文件或外部世界，也不生成查询、摘要或最终处置。因此它不能替代召回，只可能改善 Harness 已取回候选材料的选择。

一种待评估的链路是：现有历史检索形成有界候选 → jev 可选地做关联/相关性排序或预筛 → 通过来源引用读取命中附近的原始记录 → 主模型结合当前输入判断。当前 Loom 已有 `context_search` / `context_read`，以及每轮注入的 memory、threads、attention；jev 排序可能帮助召回率，也可能隐藏漏掉的候选或引入偏置，必须与“不用 jev”的基线在真实中文样本上比较。任何命中仍是历史证据，不自动成为当前事实或行动许可。

### 8.5 Pulse / heartbeat 的位置

Pulse 可以触发一次有界检查；jev 可以在该检查已取得具体候选材料后，低成本判断哪些候选值得交给主模型，或是否都应安静。jev 不能充当时钟、Inbox、持久状态或外部变化来源，也不能从空白 state 中召回不存在的证据。

因此，jev 可作候选筛选器，不是 pulse 的理由发生器。对于没有明确托付的 D，是否允许周期性扫描既有材料、扫描哪些来源、多久扫描一次以及何种变化构成 `why now`，仍未定；同一材料无变化时反复 pulse 并重复判断，不应自动视作有新机会。

### 8.6 明确托付的候选边界与未决项

C 的输入理由比自由 pulse 更强，但还不是实现合同。后续至少要确定什么表达构成明确托付，期限或触发条件如何记录，谁能取消、过期或改期，目标会话/渠道如何确定；到期时是仅把事项交回主体重新判断，还是允许执行某类动作；入队、消息送达和实际完成必须分别表述。

当前锁定依赖树中有 `@deepseek-ai/dsh-schedule@0.1.7-rc.2`，但 Loom bundle 没有挂载它。该 Schedule 插件依赖 DSH 的 Session Controller 与 `sessions.flush()`，而 Loom 由自己的 `agent-runtime` 管理单主体；它不是当前可直接使用的履行能力。其投递回执只确认 reminder 已持久进入 Agent inbox，不确认主体已执行或完成事项。

Human 已确认（2026-10 主动性方向讨论，2026-10-02）：

1. jev 只作为“已找到候选后的可选关联/排序器”，而不是召回存储或搜索器；A 先测无 jev 基线。
2. Inbox 是跨来源的逻辑输入入口，各生产者分别负责自己的持久性、授权和时效语义。
3. C 暂限定为有明确动作与未来时点/条件的委托；含糊关切不自动成为承诺。
4. Pulse 可用 jev 筛具体候选，但固定 tick 本身不创造机会；D 的周期扫描留到 C 有证据后再定。

### 8.7 C 的机制形状：到期是状态，不是事件（**已被 10-07/10-08 讨论取代，只保留两条**）

> **2026-10-09 状态更新（收敛侧）**：Human 评价本节形状"很一般"，不作定局；10-07/10-08 三轮发散已把重心移走（见 materials 两份讨论记录）。**仅以下两条保留为有效判断**：
>
> 1. **到期是状态，不是事件**（§8.7.1）——不持久化定时器，只存"上次检查过什么时候"，启动就重算"现在有什么该动"。重启、休眠、停机只把发现时刻推后，不丢。这条在 pulse 方向上同样成立（119 次布防里大量未响正是因为计时器随重启消失）。
> 2. **Harness 不对主体看不见的材料行动**（§8.7.4 前半）。
>
> 其余部分（`ahead/ahead.md` 新材料文件、12 字段条目、派生"已唤醒过"账、第一片不用 jev）**不再是当前方向**，下文保留仅作推理留痕。当前方向：解开 `deliver` 的 kind 硬编码 + 基于 jev 的 pulse（jev 退到二元 `{quiet, attend}` 门控）。
>
> 另注：§8.7.7 把"主体根本不写条目"列为最大风险，10-08 证据（attention 0 条带 horizon）证实了风险方向，但**原因判断需修正**：不是"没后果所以不写"，而是 attention 为整文件覆写、逐条时间无处可存。是载体问题，不是意愿问题。

本节是 收敛侧 自主推导的设计结论（2026-10-04，已在 2026-10 主动性方向讨论里交付），Human 尚未确认。它取代了上一版把 attention 前瞻层写成三条待确认问题的写法：Human 在同一讨论里否定的是「让主体设置定时器唤醒自己」这条路，并要求引入 Inbox 模型承载「约定时间内的近似唤醒」。下面把这条路推到可实现的形状。

#### 8.7.1 核心取舍：到期是一种状态

一条前瞻条目在它的时点之后变成「可取」，并一直保持可取，直到被取走或过期。它不是在某一时刻发出的一次性事件。

这一条决定塌掉了整个 cron 家族的需求：不需要持久定时器，不需要补偿（catch-up），不需要「错过的那次」语义，不需要时区与 DST 规则，也没有准点误差可言。重启后不恢复任何定时器，只重新读材料并问「现在有什么是可取的」。时钟漂移、机器休眠、服务停机都不造成损失——它们只是把发现时刻推后。检查可以搭在已有的时刻上（启动、停顿后的空闲、很低频的 pulse），**没有可取条目时成本为零**：不调 jev，不唤主模型。

这与「近似唤醒」互为条件：正因为到期是状态，Harness 才只需承诺「在它自己的检查时刻尽力」，才可以说「现在不合适，稍后」而不丢失任何东西。两者是同一个决定的两面，是本节最重要的互锁。

#### 8.7.2 放在哪：一个新的常驻材料文件

前瞻条目放进一个新的常驻材料文件（暂名 `ahead/ahead.md`，名字可改），与 identity / memory / threads / attention 并列，回答一个它们都不回答的问题：**什么事会回到我这里，什么时候**。

不放 attention：attention 是最易变的一层，带有自己的时效视野，会被整体改写，且 8 KiB 上限会截断——一旦截断，Harness 从磁盘看到的内容就与主体上下文里看到的不一致。

不做成 `intend()` 工具：工具产生的是配置，在两次触发之间对主体不可见；不可见的安排会越积越多，并与主体当下的理解脱节。这才是 cron 真正的失败模式，而不是「有定时器」本身。做成材料文件的收益是：过期的条目和写错的时间窗成为主体自己能看见、也能自己改掉的材料错误。

#### 8.7.3 两个写者，一份派生账

主体是该材料文件的唯一写者。Harness 只在 runtime-state 里写一份派生账：「已为 (key, due) 唤醒过」——与现有 accepted-input 去重账同构。

由此免费得到两个性质：

- 主体自己写的稳定 key 就是条目身份。换 key = 新条目；改措辞不会重新触发；**改时点会重新触发，这正好就是改期**。
- 一条安排只唤醒一次（与 after-interaction「一次停顿一次检查」同构），因此不需要额外的冷却窗口或次数上限。

#### 8.7.4 不变量：Harness 不对主体看不见的材料行动

读取用与注入相同的预算。被截断或解析失败的条目就是普通材料，永远不成为候选（截断标记本身已经在提示主体去修剪）。主体写入后，通过既有的写入预算反馈接缝回报「读到 N 条，M 行未能解析」。

Harness 不需要「已完成」状态：**完成是意义，而 Harness 不拥有意义**。它只知道自己提过一次。因此入队、送达、完成天然是三件事。过期后 Harness 停止行动但不删除条目，由主体决定丢弃、重做还是致歉。

#### 8.7.5 唤醒路径，以及第一片为什么不用 jev

检查命中后，把条目交回主体重新判断，走与 after-interaction 相同的 steer 路径；唤醒不等于履行。

jev 在这里有一个合法的窄问题：「就这一条而言，现在是不是好时机」——时间窗只说明「不再过早」。但第一片不用它，因为 C 的误判代价与 B 不同：after-interaction 判错只损失一句话，C 判错会让**一条承诺悄无声息地不被提起**。不在一条承诺前面放一个未经校准的概率闸门。

深夜之类的问题由条目自己的时间窗解决（主体写「明早」，则从本地 08:00 起可取），好过全局静默时段规则，也好过让 jev 去猜。时间用粗粒度窗口加可选 `until`，与承诺本身的近似性质相符。

#### 8.7.6 与订阅的关系：到达信封可复用，调度侧不可

**到达信封**（来源、为什么是现在、回到哪个会话、何时过期）确实是共享的：一个适配器事件就是一条 `notBefore` 已过的条目，走同一条唤醒路径。

**调度侧不能一般化**：订阅注册是一个 Effect，带凭据与远端状态，需要授权与续期，属于 runtime-state；一个 Markdown 文件不能蕴含一次订阅。条件型承诺（「构建完成时」）与订阅是同一项后续工作——两者都需要一个世界观察者。

#### 8.7.7 第一片边界与首个可观测

第一片：一次性、带时间窗的前瞻条目 → 窗口内的近似唤醒 → 交回主体重新判断。不做周期，不做条件，不做订阅，不加 jev 闸门，不承诺准点，唤醒不等于履行，Harness 不编辑主体的材料。路由上主体仍用 `message` 发往当前焦点，但情境必须说明这条承诺是在哪个会话里留下的；Harness 绝不静默改道。

最大的风险不在机制，而在**主体根本不写条目**——与 after-interaction「完全接通却在真实对话里一次没触发」同构。这是证据问题，而且观测成本很低：告诉它这个文件存在，然后看接下来几次真实承诺之后它写不写。这是部署后的第一个可观测项，排在任何阈值之前。只有当条目写得不可靠或格式不对时，才考虑加一个薄的原子写入入口（像 memory 的 note+index 那样，为一致性而非为调度）。这是本设计中最可能需要修正的判断。

## 9. 主动性的收敛形状：活动锚定的 jev-pulse（2026-10-12 收敛）

本节是当前"要建的形状"，取代 §8.5（pulse 位置待定）与 §8.7（C 的机制）。地基不变并复用：§8.1–8.4 的总原则（放弃是正常结果；三条风险轴；A/B/C/D；jev 不能召回），以及 §0–7 的 after-interaction 第一片——它已经是"按活动尾巴醒来、jev 门控、steer 交还主体"的活样板，§4a① 的自触发铁律与 §4b 的 jev-as-service 原样继承。收敛于 2026-10 pulse 收敛讨论（任务 #25），2026-10-12。

### 9.1 分界：起因在主体这边，不是外面推来的

主动性不是"多久冒一次头"——频率是结果不是来源。分界是：一个动作的起因在主体这边、还是外面递来的信号推的。钟只能管"什么时候看"，"看了之后动不动"只能是主体自己；这条外包给规则就退回成定时播报。主体自述的成功判据（materials/2026-10-08-systematic-divergence §1）：有没有哪次没被递、它自己回去碰了件远的事；而且看过不出声是正常结局、不算失败。现有 after-interaction 的 9 次真实唤醒里，已出现"自己去碰了实事"和"看完安静放过"两种，该部署已在做它自己定义的那个成功——缺的只是它唯一的"什么时候"还只活在人类输入的影子里。

### 9.2 框架：一条活动时间线，interactivity 与 proactivity 是它的两种模式

取自 Legacy Loom 的活动模型（Loom-old-archive/docs/architecture.md）：一个 Turn 跑起来就是一段 Active Segment，一直开着直到静默 30 分钟（或 2 小时上限）才冻结；推进循环空闲时等"最近一次该醒的时间"（pulse / 重试 / 退避），有新输入立即醒。取其骨架：

- 只有一条"距上次活动多久"的时钟。**活动 = 任何回合在跑**：人在聊＝interactivity，主体自己醒着做事＝proactivity，两种都刷新这条时钟。
- 人说话不是"打断一次 pulse"，是让这段活动保持热、把空闲计时往后推。主动性是这段活动凉下来、且凉过一个窗口之后自然落进去的东西——聊得越密越不会在当口冒出来，不是规则压的，是"距上次活动"还没攒够。
- 主体自己醒来做事也是活动，做完又把时钟往后推 → 不会连珠炮。

**"30 分钟"不是绝对钟点，是 time-since-activity。** 固定钟 + 人输入覆盖是被否掉的形状（Human 2026-10-12："有点回到 legacy loom 的意味"）。

**护栏（免得真滑回 legacy）：只拿这条活动时间线，不拿 legacy 的那套认知器官**（orientation / life-recorder / attention / thread / memory 维护器一堆独立大模型 + SQLite 单体，v1 已定不重建）。legacy 的 main-interaction / main-background 双模型分法同样留作以后，不在本片。

### 9.3 怎么醒：双轨

| 轨 | 触发 | jev |
| --- | --- | --- |
| 心跳（slice 1） | 活动时钟凉过窗口（静默够久） | 要：二元门控"这一刻值不值得醒" |
| 客观变化（slice 2–3） | 主体自挂的检查跑出东西 / 以后的外部事件 | 不要：理由不空，直接醒 |

- 心跳到点先看一眼：有未处理人类输入 / 正在回合里 / 刚有人说过话 → 让开。人永远压过心跳——这是活动时钟被刷新的自然结果，不是额外加的抢占规则。
- 醒 = 走 §3.1/§4 的 steer 路径把主体叫起来，带一句"此刻安静，attention/工作区在这儿，可看可推可理，也可以就这么结束"。醒了做什么它自己定；空手而归（看完什么都不做）与"做了点事"同等体面。

### 9.4 jev 的角色：退到二元 {quiet, attend}

pulse 这一片把 §2 的三档 {quiet/speak/act} 收到**二元 {quiet, attend}**：jev 只答"该不该把人叫起来"，"去说还是去做"整个交给主体（System 2）。锚 `quiet` 的保守门控（§2 的 `P(quiet)` 逻辑）继承，真实样本上该门控确在做事（见 README 运行数据）。jev 仍只提议、看不到 raw 分、绝不改状态（§1）。
兜底：若二元 jev 判得不够准，**整套结构不变**，把这个闸门换成一个轻量 orientation 子 agent。

### 9.5 为什么不会变回闹钟 / 不会扰民（这是地基）

- **空手而归真免费**：心跳到点、jev 判 quiet 就什么都不发生，没叫主模型，只花那一厘钱。所以不需要配额去压主体自造的冲动。这是 §8.7.1"没有可取条目时成本为零"在 pulse 上的落点。
- **给后果，不给配额**：配额分不出"你在忙"和"你嫌烦"，主体分得出。harness 记录每次醒之后它做了什么、人怎么反应，交还主体当可见的账，让它自己学"有用 vs 烦人"。
- **深夜**：信封换成"只做安静维护、不外发给人，除非真出大事"（沿 §4a⑤，粗粒度，不加全局硬规则）。

### 9.6 表达层（slice 2）：主体自己写检查，不是填字段表

主体要盯什么，由它**自己写一个 bash 检查**（脚本放工作区，头部写"每 30 分钟"或"到某时点"，附一句为什么盯）。harness 四件事：到点跑（子进程、超时、输出上限、连续失败自动停）、跑出东西就排进一个持久队列、队列非空问一次 jev"现在动哪条"、把每条跑过几次·主体怎么处置记成可见的账。

- 推荐理由（收敛侧，待实现期核实）：与主体现在管工作区同构（它写、harness 读，无新格式）；脚本要么出东西要么不出，没有解析自由文本的含糊；一次性提醒（C）、周期订阅、自己回看积压（D）全走这一条，不用分三种。
- 因此 **issue 02（C 的前瞻字段表）退化为"到某时点"这一种特例**；§8.7 整套 `ahead/ahead.md` 12 字段条目不再是方向。
- "到期是状态不是事件"（§8.7.1）继续成立：不存定时器，只记"上次跑是什么时候"，重启重算；判错只是推迟、队列那条还在。

### 9.7 自己的那块（self-source）——Human 已确认

设计允许主体给自己挂检查——不是人托付的，是它自己找的活。理由：它所有理由都来自人，主动性的上限就是人的记性；厚的东西只从它自己在推的线上长（materials/2026-10-07 §1、2026-10-08 §5 主体自述）。**Human 已于 2026-10-12 允许 `source=self` 并授权实验。** 防线是 9.5 的"给后果不给配额" + 9.6 那本"哪些检查从没出过东西"的账（主体自己删——它自述头一个月多半会给每条账挂检查）。后续已授权 pulse 实现（§9.12）；自写检查、通用持久队列与部署不在本轮范围。

### 9.8 建造顺序（信息顺序，blocker 在前）

1. **slice 1 心跳**：活动锚定的 jev 二元 pulse，醒来看自己那本账（attention/threads）。离 after-interaction 活样板最近——计时器（§4a⑩ `ctx.timeout`）、jev-service（§4b）、steer（§4）、§4a① 铁律都现成，几乎不新造。先交付它、拿真实体感。
2. **slice 2 自写检查 + 持久队列**（§9.6）：把一次性/周期/回看统一掉，issue 02 退化。
3. **slice 3 外部 / 世界事件**：`deliver` 的 kind 硬编码解锁（§8.7 卡点，收敛侧 2026-10-09 核：窄、低风险、四处分流接缝已在）主要给这一轨用；还需要一个"世界观察者"（§8.7.6），底座最重，最后做。

注：slice 1 心跳走**内部 steer**（和 after-interaction 一样内部直接叫醒），**不**需要 deliver 的 kind 解锁；kind 解锁留给 slice 3 的外部输入轨。

### 9.9 四处分流纪律 + 待实现核实

任何"非 user kind"的唤醒都要让这四处认得它不是真人说话（§8.7 已点、收敛侧 2026-10-09 核接缝都在）：channels 不弹"你还没回我"追问；after-interaction 不在被 pulse 叫醒的回合尾巴上挂钟（§4a①）；time-context 不更新"人类最后说话时间"；context-continuity 把这个 kind 登进 `ephemeralNoticeSourceKinds`（换代重新推导而非重读，见 §4 连续性钩子）。

**落地前要在现在代码里核实一处**：runtime 能否干净给出"距上次活动多久 / 此刻有没有回合在跑"，好让心跳锚在活动时钟而非墙上钟。after-interaction 已挂在 turn 结束 + lastHumanTurn 上，钩子应已在；写票时对着 `src/after-interaction` 与 agent-runtime 的 time-context 投影核实。

### 9.12 落地方案（2026-10-12 Human 最终确认）

Human 已授权实现，并在后续讨论明确**保留 after-interaction**。两条检查轨道独立，通过 DSH 的 Session、maintenance、inbox 接缝协作，不抽共享 projection、不互相 import。运行部署及关闭 dry-run 仍单独确认。

- after-interaction 继续在人参与的 Turn 成功结束后做 3–14 分钟检查，保留三档门控。现有 `lastHumanTurn` 记录的是人输入所在回合，不是开启者；人中途 steer 进自主回合已经满足挂钟条件，无需重命名或新来源体系。
- pulse 观察任何 `turn/end`，在静默窗口与检查间隔到期时做 `{quiet, attend}` 判断。活动与检查是两种事实；包括 shadow 与失败在内的判断尝试推进检查时刻，不篡改主体活动。
- 默认窗口、检查间隔 30 分钟，轮询 5 分钟，阈值 `P(attend) > 0.5` 仅为待校准初始值，材料预算可配置。代码生成的 prompt 一律英文，主体材料原文保留。
- 跨重启与换代时刻保存于 pulse 自己的 DSH storage-domain，Session projection 提供可恢复的当前代际回合事实；持久时间取最大值，不随 checkpoint return 回滚。不保存定时器、不补跑停机期间的 tick。
- 两轨的真人优先都监听 inbox 入队，而不是等 `user/message`；取消各自评估、只删各自待接纳 notice。已接纳的自主回合不被取消工具，真人在下个 Step 加入，记录明确标为混合来源。
- pulse 自身注册常驻工作方式说明、临时 notice 与最近自主回合执行 context；不改 identity 或 resident-context 的职责。主体仍看到原有 Session transcript、身份、memory core/index、threads index、attention 与时间，详细 thread/记忆需按需读取。
- 处置反馈只记可观察事实：来源、工具名称、错误、message 尝试/成功结果、结束原因。工具使用不自动判为完成，无工具不自动判为放下。语义理由由主体自己的材料承载；prompt 提醒在理解变化时更新，不每次强制理所有文件。
- 判断完整输入和结果只存本地 runtime 数据供复查，不进公开日志。queued 只代表入队，混合真人回合不等同于纯主动效果。

**交付**：完整插件与整栈离线验证，默认 dry-run、不启动活体。先观察真实输入下的检查行为，再经单独授权启用自主回合；shadow 不能证明主体醒来后的价值。

**关键验收**：quiet/shadow/失败不密集重查；人中途加入后正常 after-interaction；两轨互斥且任何实际回合延后 pulse；取消评估让真人进入模型、旧 notice 不混入；重启与换代保持时刻；身份、记忆索引、工作索引、材料更新与前回合上下文在真实请求中可见。没有承诺长期语义可靠、零延迟或恰好一次。
