# 47 - 测试套件在 /tmp 累积大量 loom-* 临时目录

Type: bug
Status: resolved
Blocked by: 无

## 现象

`/tmp` 下累积了 1113 个 `loom-*` 临时目录（约 130M），前缀包括 `loom-after-chat-*`、`loom-activity-closure-*`、`loom-configuration-invalid-*`、`loom-tool-trace-invalid-*` 等。一天内的多次运行即可累积上千个。

## 核实结果

- `src/` 中没有任何 `mkdtemp` / `tmpdir()` 使用（0 处）——运行时本身不创建 /tmp 目录。
- `test/` 中有约 200 处 `mkdtemp`，绝大多数没有配对清理。
- 因此这些目录是 **测试产物**，不是运行时泄漏。每次 `npm test` 运行会在 /tmp 留下约 200+ 个目录，反复运行则持续累积。
- 单独运行 `workspace/tools.test` 的 3 个测试，会稳定新增 3 个残留目录。

## 影响

低。不占生产工作区空间，但污染 /tmp；在磁盘敏感或长时间运行的开发机上会持续膨胀。

## 已定方案

- `npm test` 通过一个测试专用入口运行。
- 入口为本轮测试创建唯一的临时根目录，并通过 `TMPDIR` 让现有测试目录全部落入其中。
- 子测试进程结束后，无论成功或失败，入口只递归删除本轮拥有的根目录。
- 不扫描或清理其他 `/tmp/loom-*`，避免并发测试和其他进程互相删除。
- 不把测试产物移进 `.scratch/`；它仍然只承载开发协作材料。

## Acceptance

- [x] 完整测试通过。
- [x] 成功测试结束后不留下本轮临时目录。
- [x] 失败测试结束后也不留下本轮临时目录。
- [x] 不删除本轮测试入口不拥有的目录。

## Result

- 新增 `scripts/run-tests.mjs`，为每次测试运行创建并最终清理唯一的 `TMPDIR`。
- `npm test` 继续先 build，再通过该入口运行原有完整测试集合。
- 聚焦测试验证成功和失败退出都不残留测试根目录；独立外部目录保持不变。
- 完整测试通过，运行前后顶层 `/tmp/loom-*` 数量不变，且没有 `loom-test-suite-*` 残留。
