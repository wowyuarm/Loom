# 文档维护规则

文档导航在 [README](<README.md>)。这里仅定义 `docs/` 的写作与维护纪律；工程约束见[根指令](<../AGENTS.md>)。

## 事实归属

- 源码与测试定义当前行为。已有文档也是待核对材料，不因存在就可信；写作先查本次涉及的实现、测试和依赖版本。
- 一类事实只有一个维护落点，其它页面链接过去。架构写协作，能力页写配置与行为，指南写操作，决策记录写取舍；精确签名和默认值引用声明，不重复抄表。
- 文档先确定读者、要解决的问题和范围。参考页便于查找，指南按前提和步骤通向结果；不要在一页里混入整段研究史。
- 研究和待实现方案留在[工作记录](<../.scratch/README.md>)。能力文档写已实现事实与真实限制，不把设想写成保证。`.scratch/active/` 是未跟踪的进行中材料：可以指向 `.scratch` 这个落点，不逐条依赖其中可能解析不到的内部链接。

## 随改动维护

已落地且他人需要依赖的行为现在就写，不等“几周后稳定”。改变公开行为、模型上下文、失败恢复或工作流程时，由实现者在同一改动中更新相关页和导航；文档负责人维护结构与一致性，不成为所有事实更新的串行瓶颈。

- 新能力按职责补页，不按每个导出机械建页，也不为未存在模块预建空壳。
- 配置字段、读取时机、失败与恢复、权限、模型可见影响不可只凭邻近插件或旧文字类推。
- 操作例子要实际执行。不能执行的真实渠道、provider 或部署操作，说明验证范围；不为验证文档擅自操作活体。
- 代码路径、配置落点与命令可以出现：能帮助定位就用链接或源码/脚本入口，不用禁止路径来隐藏核对依据。机器上的服务名、账号、个人路径和凭据不写入仓库。
- 移动、拆分或删除页面时同步修复引用；归档历史不回写为当前事实。仍有效的决策留在 [adr](<adr/README.md>)，不是每次局部修改都新增记录。

## 结构与验证

中文单文件为默认语言，确有读者需求再引入翻译。标题使用读者会搜索的能力与任务词；长页加导航，入口只放短规则与链接，不用堆叠常驻上下文来替代按需读取。

段落一行，编辑器软换行；文件保持末尾一个换行。本地引用用相对 Markdown 链接，名称与 anchor 稳定。检查入口在[开发指南](<development.md>)；文档检查只验证链接与维护结构，行为正确性仍需源码、测试与实际操作证据。

能力页和交接写法见[文档与交接指南](<cookbook/documenting.md>)。
