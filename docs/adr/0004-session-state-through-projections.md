# Session 派生状态通过 Projection 重建，不新增同步历史读取

- 日期：2026-10-13
- 状态：有效

## 背景

DSH 正在减少对完整 Session 事件序列的内存保留，并已将同步的 `ownEvents()`、`snapshotEvents()` 和 `eventAt()` 标为不应新增依赖的历史读取方式。Loom 的主动性、时间、连续性和渠道判断又需要从 Session 得到可恢复的状态；如果每个插件自己扫描历史，恢复语义会分散，未来存储实现也无法替换。

## 决定

凡是运行时需要的 Session 派生状态，由拥有该语义的插件注册 DSH Session projection：projection 必须有版本化 schema、可从历史重建，并从新提交的事件增量更新。普通生产逻辑只读 projection，不新增对上述同步历史读取的调用。

需要模型按需读取历史时，使用 DSH 的异步 query/read 接缝，并明确范围和授权。连续性若确实需要完整事件序列来生成继承前缀或换代输入，必须集中在 continuity adapter，说明这是完整历史操作，而不是让其它插件复制同样的读取方式。已有的历史读取调用不因本记录自动变成合规实现，应单独迁移或记录经过审查的例外。

## 理由与代价

- Projection 是重启和换代都能重建的单一派生状态，减少“进程内看得到、恢复后看不到”的差异。
- 未来 Session 历史转为按需存储时，普通能力不必跟着改变。
- 每个新状态都要设计 event fold、schema version 和缺失能力的行为；短期比临时扫描多一些工作。
- Projection 不是第二事实源，删除注册只表示该能力不再提供该派生视图。

## 重审信号

- DSH 提供了稳定的异步完整历史读取接口，并且 continuity 不再需要在 adapter 内自行组装完整序列。
- 某个状态无法由 Session 事件可靠重建，且缺少可持久化的事件字段；此时应先补事件契约，而不是恢复任意扫描。
