# Execution Workflow

本文档适用于实现、验证和交接的 Agent。它与协作工具无关；任务可以来自本地 tracker、代码托管平台或团队协作系统。

## 开工

1. 阅读 `AGENTS.md`、任务合同和直接相关的正式文档。
2. 确认目标、范围、依赖、完成证据和授权；有缺口就停下并指出，不猜测产品决策。
3. 认领任务作为执行锁，使用独立 worktree，确认基线和工作区状态。
4. 只修改合同覆盖的范围；不要把过程记录、凭据或个人 Instance 材料带入提交。

## 验证和交付

- 先跑改动所在层的最窄充分测试，再按合同或横切风险扩展到全量。
- 运行 typecheck、必要的构建和 diff 检查；真实运行验收由明确的运行/产品角色执行。
- 固定一个候选提交，报告改动、测试证据、剩余边界和下一位动作。
- 实现完成不等于可合并；合并、部署、迁移和产品验收分别需要明确放行。
- 没有部署授权时只交付候选，不操作生产环境。

## 交接与失败

交接材料必须包含稳定提交、如何验证、已知限制、未决问题和恢复入口。执行中发现合同冲突、共享工作区冲突或无法证明结果时，停止扩大范围并回到任务入口升级；不要用反复重试掩盖确定性问题。

`implement` 用于已有完整合同的实现，`tdd` 用于需要测试先行的改动，`handoff` 用于真实所有权交接。Skills 是工具，不替代任务合同和代码评审。
