# 防御性工程规则

本文档适用于生命周期、并发、子进程、回调和文件删除。防御性代码只针对已经存在、边界上合理可预见，或一旦发生会造成明显损失的故障；不为静态类型已经排除或纯粹假设的情况增加分支。

## 生命周期和并发

- 一次异步操作只有一个完成、取消和回滚所有者。若 readiness、reservation 或 settlement 有独立生命周期，就给它独立所有者；否则收进同一个 controller 或 transaction。
- 异步状态不是同步结果。全局 `running`、`idle` 或事件回调不能冒充某条消息、某个任务或某次 follow-up 的完成；需要因果结果时显式定义该操作的开始和结束。
- `stop` 或 `dispose` 必须等待子任务真正停止。先关闭新的 listener/notification，再发出 abort 或 kill，最后等待子任务退出，避免迟到结果重新发布状态。
- 外部 callback 抛错不能破坏核心调度，也不能阻止后续 callback；dispatcher 负责隔离并记录失败。

## 公开结果和恢复

- 一个操作可同时具有多个正交结果时分别保存，不因其中一个结果成立就丢失其他事实。
- 实现收到同一结果的多种表示时，在公开接口前归一化；错误来源、取消、超时和部分完成必须让调用方可区分。
- 发布状态前先完成权威提交。缓存、Prompt、UI、恢复视图和通知从已提交事实派生，不能先宣布成功再写入。
- 清理和回滚是原操作的一部分。清理失败不得覆盖原始失败；无法证明最终状态时返回 uncertain 或等价的显式状态，不猜测是否可重试。

## 进程和文件

- 运行不可信命令时使用最小环境变量和私有随机临时目录，临时文件使用独占创建和 owner-only 权限。受控的 Raft CLI、git 或明确注册的服务按其认证合同传递环境，不机械清空。
- 可能是 symlink 或 Windows junction 的路径先用 `lstat` 判断，只 unlink 链接；递归删除只用于已证明的真实目录，不能跟随链接进入目标。
- 子进程 teardown 采用 kill/abort 后等待完成的顺序；超时、signal 和 exit code 分别记录。

每条新增防御路径都要说明它防止的具体失败，并用对应测试证明错误路径；能用现有结构直接处理时不增加抽象，没有当前风险或消费者时不增加兼容层、状态机或 fallback。
