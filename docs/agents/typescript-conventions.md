# TypeScript 约定

本文档适用于 Loom 的 TypeScript 源码和测试。它只记录跨模块长期成立的规则；具体模块行为仍由代码、测试和对应正式文档定义。

## 类型和边界

- 保持 ESM 和 NodeNext 语义；源码内相对导入使用运行时可解析的 `.js` 后缀。
- 优先让类型系统表达同进程内的约束。静态接口已经保证的值不重复校验，也不为不可能的输入增加 fallback。
- 在配置、模型或工具 JSON、Channel/wire、文件、数据库恢复数据、子进程等边界解析 `unknown`，校验后再进入类型化代码。
- 避免无界 `any`。上游库要求泛型占位时可以使用，但不要让 `any` 继续扩散到 Loom 自己的领域值。

## 分支和结果

- 关闭的联合类型按 discriminant tag 分支。完整映射必须穷尽；返回 `void` 或只处理部分成员时，显式列出忽略的成员或在 `default` 说明其含义，不能依赖静默落空。
- 同一公开结果可能来自 throw、状态值或流事件时，在公开接口前统一语义，调用方不猜测来源。
- 互相独立的结果分别表达。例如 timeout、exit code 和 signal 可以同时成立，不能用一个分支遮住另一个事实。
- 规则在真正执行决定的位置强制。Prompt、schema 省略、外围过滤或调用顺序不能替代执行层检查。

## 默认值、状态和限制

- 配置或装配层负责一次性解析部署相关默认值；下层执行代码接收已解析值，不用隐藏的 `?? default` 改变运行选择。协议常量、安全不变量和仅用于依赖注入的测试默认值可以固定在其所有者内。
- 能在加载时发现的配置错误立即失败；需要运行信息才能判断的错误在最早可判断处失败，不静默跳过。
- 状态、事件和派生视图只在权威写入提交成功后发布，并从同一个权威来源投影。
- byte、token、item 和 time 限制在完整保留值或输出值已知的位置执行，包含 wrapper 和 metadata；测试极小值、精确边界、单个超大项和多字节文本。
- 模型实际看到的事实必须有明确来源：运行与恢复事实来自 Runtime Store，执行证据来自 Primary Agent Transcript，身份、行为和记忆来自 Agent Workspace。新的动态输入先建立权威证据，再投影给模型，不能只存在于临时内存或说明文字里。

## 错误、注释和接口

- `catch` 只包真正允许失败的操作。吞掉异常时说明吞掉的具体失败以及为什么不影响权威状态；清理失败不能覆盖原始错误。
- 注释和 JSDoc 写代码看不出的行为、失败、时序、所有权和安全使用条件，不复述控制流，也不保留实现或评审过程。
- Prompt、工具说明、结果和诊断只使用模型完成任务需要的概念，不泄漏 UI、传输层或内部实现词。
- 新抽象、状态、选项和兼容路径必须有当前消费者或当前合同；成熟依赖能真实删除自有代码和测试时优先使用。

跨模块、持久化或 wire 中的 opaque id 迁移为 branded type 是独立横切工作；完成迁移前不把它写成当前仓库已经满足的硬规则。
